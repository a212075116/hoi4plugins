# 摄像机只读适配器

2026-10-14：第一步已交付为独立外部 Python 只读工具，未接入生产 DLL，不改摄像机写入或 hook。
入口为 ImageBindings 与 CameraReader.snapshot，模块在 test/modules/camera，仍是有限能力原型。

## 自动定位与明确保留的依赖

- RTTI 精确类名 → TypeDescriptor → COL → 主虚表，检查 signature/self/hierarchy/节与主次级 offset，拒绝缺失/歧义。
- 在主表找符合有限指令形式的 leaf getter，不预填虚槽/getter RVA；不同函数候选仍拒绝。
- 实际槽37/38指向同一个 getter，是别名，不当作不同函数。运行时再次检查所选槽和代码。
- 扫描映像可写节的指针并核对对象首部，未预填全局槽 RVA，不扫整个堆，不创建游戏对象。
- 多个根引用同一 Idler 合并，多个不同 Idler 则拒绝。实机自动找到根 RVA 0x332F698、0x332F6A0。

SHA profile 仍声明 camera pointer 字段和高度/上下限布局；getter displacement 须符合 profile。
当前 SHA `7dc947be34970da1e1c787bcddbe7f62b610ff258aebf8f06aa8b348f3a031d5` 开放运行时读取。
backup SHA `46ebb324d734a2966e81681afdae77bbc23ff6a8be864ccf833495211a8c7e39` 只通过离线 getter 验证，不开放运行时字段读取。
未知 SHA 可取得 RTTI 诊断，但不能套用已知布局读摄像机，更没有写功能。
profile 没有固定根/表/getter 地址；字段合同仍需按构建核对，不是全自动 ABI 迁移。

## 读取合同

进程权限仅 PROCESS_QUERY_INFORMATION | PROCESS_VM_READ（0x410），没有写内存、远程线程或虚调用。
从实际模块路径取得基址并核对 PE headers；仅允许 ImageBase 为首选值或实际加载基址，不忽略其他差异。
本次观察到 ASLR 后 header.ImageBase 正常更新，已增加回归。
主菜单 CFrontEndIdler 返回 NOT_IN_MAP，不读 camera 指针/字段；加载时 OBJECT_MISSING 可稍后重试，不重启。
读取前后核对对象、根、camera 指针、getter 及两份值块，不一致明确拒绝。
这不是游戏线程上的原子 snapshot，不能排除检查间 ABA/瞬态变化；不缓存裸对象供下次无条件使用。
目前不调用游戏函数，不存在外部线程冒充游戏线程；未来调用须另行实现调度/生命期合同。

成功为 READY_READ_ONLY，含对象、根、动态 getter 槽、高度/上下限和 writes=false。
height 是现有 OFF_CAM_HEIGHT=0x69C 的目标高度，不是0x678的插值后即时高度。
失败可为 UNREVIEWED_PROFILE、TABLE/GETTER/OBJECT_MISSING 或 AMBIGUOUS、NOT_IN_MAP、GETTER_CHANGED、READ_FAILED、STATE_CHANGED、INVALID_VALUES 等。
CLI 成功 exit0，拒绝/失败 exit2；OFFLINE_BOUND 只表示静态绑定，不等于运行时可用。

## 验证与边界

两映像自动恢复 getter，别名槽均37/38，RVA分别0xDC53B0 / 0xDB3F60。
当前独立 CHI 中20次与原 Camera_GetObject/字段路径的外部读取对照全部一致：目标高度310、范围50～3000。
正常关闭CHI后启动菜单，实机返回NOT_IN_MAP；没有强杀、Frida或计时结束进程。
29场景覆盖重复根、未知/离线profile、菜单、缺失/歧义、不可读内存、异常值、状态变化、headers及离线RTTI/getter破坏。
受控内存测试不冒充实机；没有用backup搭配当前硬RVA插件启动，更未宣称第二映像实机通过。
方法见[测试说明](../../test/docs/camera_read_adapter.md)。本轮止于可用只读能力和失败报告，不扩大到所有RVA或生产写路径。
