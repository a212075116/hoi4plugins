# 跨版本定位与适配层

2026-10-14：[原生摄像机闭环](原生摄像机适配与功能状态.md)已接入生产插件；外部原型记录仍保留。不宣称完整自动跨版本兼容。

## 目标

业务模块依赖我们维护的稳定接口，版本变化集中到底层；不是找到一个万能导出就能永久兼容。
例如 GetCameraHost、ReadCameraHeight、RegisterEffect、FormatTooltip 等职责；这些是设计示例，不是现有实现。
不暴露任意“对象+槽号调用”，否则 ABI 依赖只是换了位置。对象仍要遵守状态、线程及生命周期限制。
若要给其他插件提供类似 Source 的工厂，可由本插件导出版本化 C ABI，使用 opaque handle、结构大小、能力标记及明确错误码。
那是“我们提供的稳定 API”，不是凭空让 HOI4 内部 C++ ABI 稳定；旧接口兼容由我们在适配层维护。

```text
业务 Effect / Trigger / Console
          ↓ 稳定能力接口
      版本适配与依赖门控
          ↓ 已验证绑定集合
 RTTI / 注册名 / xref / 指令语义 / 已知映像 profile
          ↓
      当前 HOI4 映像与活对象
```

## 分开解决四种问题

| 问题 | 首选策略 | 不能假定 |
|---|---|---|
| 虚表移动 | RTTI 类名、COL、主次级子对象校验 | 类名唯一、虚槽顺序不变 |
| 非虚函数/全局槽移动 | 注册名/文本引用、函数关系及指令语义、多锚点模式 | 一个短 AOB 永远唯一 |
| 布局/签名变化 | 每构建的布局/调用合同 profile，合法 getter，有限指令语义恢复 | 原 getter 槽永不变、同地址仍同义 |
| 状态/生命期 | 经验证对象取得路径、类型与状态门控、执行线程 | 静态 vtable 等于活对象 |

## 解析与启用

每绑定记录：逻辑名、模块 SHA、候选集合、推导链、节范围、主次级 offset、ABI/布局合同、依赖功能及验证状态。
已知 SHA profile 可快速加载，版本字符串只作显示；未知构建先生成候选报告，不能静态匹配到就直接执行。
后续证实某类变化只是地址位移，再为该合同开放“自动校验后运行”。
多候选、缺失或语义不符则 fail closed，禁用完整依赖组，不能保留部分 hook 并伪报 ready。
解析与写入分两阶段：全部前置合同通过再安装，避免装到一半才发现依赖缺失。

AOB 只是候选发现手段。按指令边界处理 RIP-relative、分支位移等变化项，结合注册名/xref、调用关系和函数形态。
不能把所有立即数都 wildcard，否则会抹掉区分功能的常量。内联、优化及代码重排都可能破坏旧模式。
函数地址恢复仍需核对签名、参数布局、所有权和虚槽语义。内部注册器不是官方稳定 ABI。

## 本次证据

工具 `test/tools/research_native_interfaces.py` 只读 PE、依赖 pefile，不启动游戏、不安装 hook。
当前 exe 为 9433 个通过本工具结构判据的虚表候选、8960 个不同类型名；backup 为 9425 / 8951。
各自恰好一个候选的同名类型交集 8387，所有配对表 RVA 都发生位移。
这是候选统计，不等于全部游戏类型，更不是 8387 个 ABI 已迁移成功。
业务相关表、多继承案例及 SHA 见[接口复核](有没有官方接口.md)。

## 有限实施顺序

1. 先做摄像机只读路径：Idler 主表、状态、getter/读取语义、profile 及失败报告，未知版本默认不写。
2. 用两份映像做定位回归，再在对应可运行环境验证对象/线程和读值，不能同一进程冒充两个版本实机测试。
3. 再迁移 Effect/Trigger 模板、工厂、map、参数/分配器合同；tooltip/free 不能只靠地址匹配。
4. 最后处理 hook、变量、持久化、成就等高耦合路径，各自保留依赖门控和原语义回归。

第一步交付是一个可用只读能力与可解释的失败报告，不是先替换所有 RVA 或开启无限重构。
若 RTTI 被移除/改名，或槽位/字段/调用合同变化，就用版本差分定位变化，集中修改适配器。
源码可见 70 处 RVA 宏定义、63 个不同文本数值；不含全部字段/槽位/内联地址，不能当成总迁移清单。
两映像 PE FileVersion 都是 1.0.0.0，本次按 SHA 区分，不虚构发行版本归属。

可以追求“小更新大部分定位自动恢复，人工工作集中适配层与回归”，不能保证未知未来版本零维护。
一手来源见[公开接口参考](公开接口与跨版本定位参考.md)，运行方法见[研究测试说明](../../test/docs/native_interface_research.md)。
