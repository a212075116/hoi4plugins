# 虚表索引表

> 生成脚本：test/probes_ida/vtable/build_vt_index.py
> 查询工具：test/probes_ida/vtable/vt_query.py
> 产物：sources/1.19.3/vt_index_1.19.3.json（大文件，不入 git）

## 它是什么

把 hoi4.exe 里**全部虚表**扫一遍，为每个虚表记录：

| 字段 | 含义 |
|---|---|
| rva | 虚表在 image 内的偏移 |
| sym | IDA 给出的符号名（如 ??_7CGameApplication@@6B@） |
| cls | **由 RTTI 反查得到的类名** |
| nbase | 继承链上的基类数 |
| n | 虚表槽数 |
| slots | 每个槽指向的函数 RVA 列表 |

**cls 与 sym 是两条独立来源** —— 前者读内存里的 RTTI，后者来自 IDA 符号表。
两者一致才说明数据可信。

## 生成方式

    python test/probes_ida/vtable/build_vt_index.py <输出.json> [只跑前N个]

步骤：

1. 用 IDA 的符号表取全部 ??_7 符号作为候选起点（12333 个）
2. 对每个候选：读 vftable-8 得 COL，按 RTTI 解析类名与基类数
3. 从起点起读连续内存，逐个槽判定指针是否落在 image 内
4. 输出 JSON

实测速度：30 个约 1.8 秒，全量约 12 分钟。

## RTTI 读取的关键陷阱

**这个 exe 的 RTTI 指针字段是 4 字节 RVA，不是标准 MSVC x64 的 8 字节绝对地址。**

COL 布局（实测字节）：

    +0x00  uint32  signature       必须 == 1
    +0x04  uint32  offset
    +0x08  uint32  cdOffset
    +0x0C  uint32  pTypeDescriptor  ← RVA
    +0x10  uint32  pClassDescriptor ← RVA

读法：

    col    = *(uint64_t*)(vftable - 8);
    tdRva  = *(uint32_t*)(col + 0x0C);
    td     = imageBase + tdRva;
    name   = (char*)(td + 0x10);          // .?AV<ClassName>@@

按 8 字节读会拼出 0x2cdec0802cdec30 这类垃圾值，表现为「类名是乱码」。

## 查询工具

    python vt_query.py <index.json> stats                 总体统计
    python vt_query.py <index.json> find  <关键字>        按类名/符号名模糊查
    python vt_query.py <index.json> cls   <类名>          精确查某个类的全部槽
    python vt_query.py <index.json> slot  <槽RVA>         哪些虚表用了这个槽
    python vt_query.py <index.json> shared <最少类数>     被多个类共享的槽

典型用法：调某个虚函数前，先用 cls 查出目标类的槽布局；
或用 slot 反查某个已知函数被哪些类共用（判断它属于哪个基类接口）。

## 验证：已知事实能否被索引表复现

之前我们用 Frida 实证过：CInGameIdler 的虚表槽 +0x130 是 sub_140DC53B0（cam getter）。
索引表给出的结果：

    CInGameIdler  rva=0x02968ff0  n=64  nbase=7
        槽[37] = +0x128  ->  0x00dc53b0
        槽[38] = +0x130  ->  0x00dc53b0

**与运行时实证一致。**

## 两点容易误解的地方

### 1. 一个类可以有多个虚表

多继承时每个基类子对象各有一份虚表。实测：

| 类 | 虚表数 |
|---|---|
| CInGameIdler | 4 |
| CArmy | 4 |
| CTaskForce | 4 |
| CUnit | 3 |
| CGameState | 2 |
| CCurrentGameState | 2 |

**用类名查虚表时必须处理"一个名字对应多个表"的情况**，
否则会拿到错误的那一份（我第一次写验证脚本就踩了这个）。

### 2. CGameState 与 CCurrentGameState 是不同的类

| 类 | 虚表 RVA |
|---|---|
| CGameState | 0x027210e0 / 0x02721138 |
| CCurrentGameState | 0x02721158 / 0x027211b0 |

早期我把 0x2721158 当成 CGameState 的虚表，实际它是 **CCurrentGameState** 的。

## 已知局限

- slots 只判定「指针落在 image 内」，**没有区分代码段与数据段**。
  少数槽可能指向数据（如 RTTI 结构自身）。调用前需自行确认可执行。
- sym 来自 IDA，模板名可能被截断（如 ?$ctype@D@std）。
  cls 来自 RTTI，是完整的。**判断类身份应以 cls 为准。**
- 索引表与游戏版本强绑定。版本一变，全部 RVA 作废。
