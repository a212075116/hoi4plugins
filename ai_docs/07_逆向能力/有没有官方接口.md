# 有没有官方接口

> 2026-10-14 复核：本地两映像、PDXSDK 导出/RTTI 只读扫描，以及 Valve / LLVM / HOI4 官方资料。

## 结论

**旧版无条件“没有”的结论撤回。当前尚未建立可供本项目依赖、类似 Source 版本化 CreateInterface 的 HOI4 游戏内核公开 C++ 接口合同证据。**
这不是证明所有模块都没有内部工厂，也不意味着更新必须从零逆向。

## 证据一：hoi4.exe 导出表

110 个导出，构成如下：

| 类别 | 数量 | 说明 |
|---|---|---|
| PHYSFS_* | 108 | PhysicsFS 文件系统库（虚拟文件系统） |
| AmdPowerXpressRequestHighPerformance | 1 | 显卡驱动开关变量 |
| NvOptimusEnablement | 1 | 显卡驱动开关变量 |

本次重新读取 hoi4.exe 与 hoi4.exe.backup，均为 110 导出，108 个是 PHYSFS C++ 修饰名。
未发现 CreateInterface / GetInterface / Factory 命名导出，只能排除这些直接命名入口，不能由此排除其他名称、其他 DLL 或未导出的内部注册器。

## 证据二：PDXSDK.dll

本次重新读取为 1165 导出，其中 1136 个名称含 Model，其余也有 SDK 层符号；旧称“全是 Model”不精确。
符号包含账号、Mod、云存档等客户端功能，未发现上述命名工厂；不能只按导出名认证所有接口用途或证明它不间接关联游戏。

## 证据三：外部检索

旧检索没有找到 native 插件 API，不是“不存在”的证明。
本次核对的一手资料支持官方脚本/数据 modding；没有取得游戏内核的版本化原生 ABI 合同。
Source 的工厂按注册名精确返回接口对象，不是给任意 C++ 类名就返回所有虚表；兼容来自共享声明和版本合同，而非工厂名字本身。
出处见[公开接口参考](公开接口与跨版本定位参考.md)。

参考：https://hoi4.paradoxwikis.com/Modding

## 那 mod 到底怎么扩展游戏

HOI4 的官方扩展方式是**纯数据驱动**：

| 层 | 载体 |
|---|---|
| 脚本 | .txt（Lua 风格 DSL） |
| 定义 | common/defines/*.lua |
| 界面 | interface/*.gui |
| 本地化 | localisation/*.yml |

这些**不接触二进制**，因此不需要任何 native 接口。

## 所以我们只能自己造

内部注册器、RTTI、字符串/xref 和指令语义可以成为自动定位锚点，不必逐个手改全部 RVA。
本次工具未输入下表中的 RVA，即在两映像中找回了这些候选：

| 主虚表 | 当前 exe | backup |
|---|---|---|
| CAddStabilityEffect | 0x276EDF8 | 0x2746A98 |
| CFrontEndIdler | 0x2949D50 | 0x29217B0 |
| CInGameIdler（COL.offset=0） | 0x2968FF0 | 0x2940240 |

当前 CAddStabilityEffect 与源码 RVA_STAB_VT 一致；CInGameIdler 各另有 offset=0x5F0 的次级表，不能假定类名唯一。
两主表 0x130 字节槽指向 0xDC53B0 / 0xDB3F60，离线反汇编均读取 self+0x750 后返回；不是本次重新做过实时调用。
两映像 FileVersion 都是 1.0.0.0，仅凭 backup 文件名不能断定发行版本，完整 SHA 见研究报告。

没有官方工厂也能自建稳定适配接口：自动恢复地址、校验 ABI/布局与依赖、歧义时禁用相关功能。
**找回虚表不等于拿到活对象，更不等于证明槽位/签名/生命周期跨版本不变。**
当前[原生摄像机只读闭环](原生摄像机适配与功能状态.md)已接入生产插件，其他模块未自动迁移；完整方案与边界见[跨版本定位与适配层](跨版本定位与适配层.md)。

**这条路是通的，见《虚表与RTTI》。**
