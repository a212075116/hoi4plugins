# 有没有官方接口

> 依据：dumpbin 读导出表 + 两轮外部检索

## 结论

**没有。** HOI4 不像 Source 引擎那样提供 CreateInterface 式的插件接口工厂。

## 证据一：hoi4.exe 导出表

110 个导出，构成如下：

| 类别 | 数量 | 说明 |
|---|---|---|
| PHYSFS_* | 108 | PhysicsFS 文件系统库（虚拟文件系统） |
| AmdPowerXpressRequestHighPerformance | 1 | 显卡驱动开关变量 |
| NvOptimusEnablement | 1 | 显卡驱动开关变量 |

**没有任何 Create / GetInterface / Factory 字样的导出。** 游戏对插件不设入口。

## 证据二：PDXSDK.dll

1165 个导出，全是 PDX::SDK::Model::* —— 账号、Mod 订阅、云存档、好友之类的
**客户端 SDK**，与游戏内核无关。

## 证据三：外部检索

两轮检索（Paradox HOI4 native plugin API / Clausewitz engine native plugin hook）
都只找到脚本层 modding（Lua + XML 定义文件），**没有 native 插件 API 的资料**。

参考：https://hoi4.paradoxwikis.com/Modding

## 那 mod 到底怎么扩展游戏

HOI4 的官方扩展方式是**纯数据驱动**：

| 层 | 载体 |
|---|---|
| 脚本 | .txt（Lua 风格 DSL） |
| 定义 | common/defines/*.lua |
| 界面 | interface/*.gui |
| 本地化 | localisation/*.yml |

这些**不接触二进制**，因此不需要任何 native 接口。

## 所以我们只能自己造

要走「调用游戏内部函数」这条路，只能靠**逆向恢复**：
找到对象 → 读它的虚表指针 → 按索引调用。

**这条路是通的，见《虚表与RTTI》。**
