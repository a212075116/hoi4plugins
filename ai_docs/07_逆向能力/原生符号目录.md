# 原生符号目录：第三轮

2026-10-17，插件业务模块的硬编码RVA已集中到符号目录；不是所有字段偏移、内联地址或ABI已跨版本认证。

## 结构

| 位置 | 职责 |
|---|---|
| `src/plugin/adapter/symbol_catalog.h` | X-macro清单：10个组、53个符号；唯一的增删入口 |
| `src/plugin/adapter/native_symbols.inc` | 启动解析：读资料、RTTI索引、逐组校验与发布 |
| `bindings/<SHA>.symbols` | 每映像资料：批准位与CODE/DATA地址 |
| `test/tools/migrate_native_symbols.py` | 从已审核映像生成新映像候选，不批准 |

业务只调用`NativeAdapter_Symbol(NSY_*)`与`NativeAdapter_GroupReady(NG_*)`；组未就绪时符号值为0，业务必须先检查组。
与摄像机`.profile`、脚本`.registry`独立；三者都按映像SHA256命名，启动时加载，不热重载。

## 符号种类

| 种类 | 资料中 | 启动校验 |
|---|---|---|
| CODE | `RVA:16字节小写hex` | 执行节，file与loaded代码一致，指纹逐字节相等 |
| DATA | `RVA` | 声明字节数完整落在可写节；不接受指纹 |
| TABLE | 不出现 | RTTI类型名+子对象offset唯一表，声明槽数均为执行地址，loaded表未改 |
| SLOT | 不出现 | 同TABLE，再取槽，loaded槽与代码未改 |

SLOT/TABLE由类型名推导，不手填；同名多表、表过短或loaded改动均拒绝。

## 组与门控

组声明：名称、是否依赖脚本registry、最多两个前置组。顺序即依赖顺序，前置未就绪则后继关闭并报`DEPENDENCY_<名>`。
资料key集合必须精确等于schema/image_sha256/contract、每组`approve.<名>`、全部CODE/DATA key；多、少、重复、非ASCII、NUL均整体拒绝。
单组内首个失败符号决定原因（如`SYMBOL_var64.lookup:FINGERPRINT_MISMATCH`），整组值清零，不留部分可用地址。
其他组不受影响：var64关闭时console、achievement仍可就绪。

`camera_write`与`imports`目前没有符号，批准即就绪；它们是门控占位，不代表已验证任何地址。

## 迁移工具不是批准器

一键入口`test/tools/migrate_image.py --image <exe>`：同次运行生成`.symbols`、`.registry`与摄像机`.profile`候选和总报告。
引擎在`migrate_native_symbols.py`，`.registry`键与`.symbols`走同一套恢复；旧`migrate_script_bindings.py`保留但已被覆盖。

1. CODE先用基准函数屏蔽模式（RIP位移、分支位移、重定位字节）找唯一函数起点；无`.pdata`叶函数接受不在任何unwind范围内的命中。
2. 模式缺失或歧义时用调用者共识；DATA只用引用者共识。锚点函数本身也变了时，第二轮按调用者共识再跳一层求锚点孪生。
3. 锚点内引用指令先按同序号比屏蔽字节，不同时用前后各2条指令的屏蔽窗口在孪生函数内唯一对齐。票必须全体一致。
4. DATA结果须与基准落在同类节（可写/只读/执行标志相同）且声明长度不越节。
5. CODE另取lea引用的ASCII专属字符串（≥8字节）投票：结构方法失败时作后备，成功时作交叉校验。
6. SLOT：目标槽函数须与基准槽函数屏蔽形态相同，或基准槽函数孪生正是目标槽；孪生落在别处报`SLOT_FUNCTION_MOVED`并关组。
   虚表槽数变化及无法验证的槽只作复核标记，不关组。
7. registry的`static_token_count`不手猜：数组尾地址作为独立DATA迁移，计数=(尾-头)/72，须整除。
8. 摄像机：四个偏移优先取字段见证一致值（见下节），否则沿用基准；指针偏移须有RTTI getter；仍须实机读值。

不同SHA输出永远全部禁用（`approve.<组>=0`、`runtime_registration=0`、`runtime_read=0`），未解析写0；`--rescan`同SHA强制重扫作自检。
复核标记：`SINGLE_ANCHOR`、`DELTA_OUTLIER`（同组位移相差均>1MB）、`STRING_DISAGREES`、`SLOT_UNVERIFIED`、`TABLE_SLOT_COUNT_CHANGED`。

capstone 5.0.7对带`66`前缀的SSE RIP操作数报`disp_size=2`；x64 RIP位移恒为4字节，扫描核心与旧registry工具均按4屏蔽。
候选只证明形态唯一，不证明签名、参数布局、所有权或语义不变。结构体字段偏移（`SDK_RVA`内）仍不在迁移范围。

## 字段偏移（第五轮）

`test/tools/native_fields.py`列出`SDK_RVA`中54个游戏对象字段偏移（摄像机、CGameState日期、var64、参数/选择器、触发器、成就管理器、控制台管理器）。
MSVC std::string/vector/哈希节点布局（+16大小、+24容量、SSO 15、节点+24/+32/+40）属编译器ABI，有意不列。
`check_native_fields.py`（并入`migrate_image.py`）做静态分诊：

1. 见证池：已迁移的catalog/registry函数，加相关RTTI类型（catalog类型、四个脚本模板、两个Idler）同序号虚槽，共约356个函数对。
2. 见证：基准函数中非栈寄存器（非rip/rsp/rbp）内存操作数位移等于该偏移的指令。
3. 目标：在孪生函数内按屏蔽全部位移的指令形态对齐（同序号或前后2条唯一窗口），读新位移。
4. 全体一致为`SAME`/`MOVED`；≥90%且异议≤2为`MOSTLY_SAME`；其余`SPLIT`。只有一致`SAME`不需复核；<0x40或见证>40另标低特异/噪声。

见证不绑定所属对象，同位移的其他类字段会混入（如exe3中CArmy槽为`gamedate.raw`投票），所以它是分诊而不是证明。
摄像机资料迁移改为：四个摄像机字段若见证一致则用见证值，否则沿用基准，再用RTTI getter校验指针偏移。
生产代码的偏移仍是常量，本轮不改；资料化字段需另一轮改动业务模块。

| 目标 | SAME | MOSTLY_SAME | MOVED | SPLIT/未对齐 | 无见证 |
|---|---|---|---|---|---|
| 当前自扫 | 50 | 0 | 0 | 0 | 4 |
| backup | 47 | 3 | 0 | 0 | 4 |
| exe3 | 13 | 4 | 7 | 26 | 4 |

无见证：`camera.maximum`、`gamedate.month_days`、`gamedate.day`、`var64.mark`（插件自有标记，本无原生见证）。
backup三项`MOSTLY_SAME`为78:1、9:1、366:1，实机已证backup偏移未变，即见证噪声。
exe3的`camera.object_to_camera` 7见证一致为`0x728`；独立核对exe3的`CInGameIdler`槽36/37正是`mov rax,[rcx+0x728]; ret`，确认真实布局变化。

## 速度

`rip_references`改为每映像一次建立`pos+4+disp`排序索引（int32，约300MB/映像），查询二分；调用方声明需要的引用种类和函数数，验证提前停止。
限量时按跨步顺序取样，锚点池取8倍后按函数长度降序选12个，避免一串相同小桩函数全部歧义。
多数票达≥5、≥90%且异议≤1时作为候选并标`ANCHOR_DISSENT`（backup的`param.get`为10:1）。三映像并行由753秒降为126秒，三类资料与上一轮逐字节相同（exe3摄像机另外定位成功）。

## 新版本流程

1. `migrate_image.py --image <新exe> --symbols-fixture <夹具exe>`，读`migration.json`各部分的未解析与`review`。
2. 逐个确认候选，未解析项用IDA/xref补，手工写入资料并说明依据。
3. 把审核过的组改为批准，复制到`bindings/`，用`live_bindings_check.py`实机启动并检查功能日志。
4. 需要的脚本行为回归通过后再提交资料；未验收组保持0，业务按组门自动跳过。
