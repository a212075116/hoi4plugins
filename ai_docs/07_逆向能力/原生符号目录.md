# 原生符号目录：第三轮

2026-10-17，插件业务模块的硬编码RVA已集中到符号目录；不是所有字段偏移、内联地址或ABI已跨版本认证。

## 结构

| 位置 | 职责 |
|---|---|
| `src/plugin/adapter/symbol_catalog.h` | X-macro清单：10个组、53个符号；唯一的增删入口 |
| `src/plugin/adapter/native_symbols.inc` | 启动解析：读资料、RTTI索引、逐组校验与发布 |
| `bindings/<SHA>.symbols` | 每映像资料：批准位与CODE/DATA地址 |
| `test/tools/migrate_native_symbols.py` | 从已审核映像生成新映像候选，不批准 |

业务只调用`NativeAdapter_Symbol(NSY_*)`与`NativeAdapter_GroupReady(NG_*)`；组未就绪时符号值为0，业务必须先检查组。
与摄像机`.profile`、脚本`.registry`独立；三者都按映像SHA256命名，启动时加载，不热重载。

## 符号种类

| 种类 | 资料中 | 启动校验 |
|---|---|---|
| CODE | `RVA:16字节小写hex` | 执行节，file与loaded代码一致，指纹逐字节相等 |
| DATA | `RVA` | 声明字节数完整落在可写节；不接受指纹 |
| TABLE | 不出现 | RTTI类型名+子对象offset唯一表，声明槽数均为执行地址，loaded表未改 |
| SLOT | 不出现 | 同TABLE，再取槽，loaded槽与代码未改 |

SLOT/TABLE由类型名推导，不手填；同名多表、表过短或loaded改动均拒绝。

## 组与门控

组声明：名称、是否依赖脚本registry、最多两个前置组。顺序即依赖顺序，前置未就绪则后继关闭并报`DEPENDENCY_<名>`。
资料key集合必须精确等于schema/image_sha256/contract、每组`approve.<名>`、全部CODE/DATA key；多、少、重复、非ASCII、NUL均整体拒绝。
单组内首个失败符号决定原因（如`SYMBOL_var64.lookup:FINGERPRINT_MISMATCH`），整组值清零，不留部分可用地址。
其他组不受影响：var64关闭时console、achievement仍可就绪。

`camera_write`与`imports`目前没有符号，批准即就绪；它们是门控占位，不代表已验证任何地址。

## 迁移工具不是批准器

`migrate_native_symbols.py`读取基准映像的已审核资料，对目标映像逐符号找候选：

1. CODE先用基准函数的屏蔽模式（RIP位移、分支位移、重定位字节）在目标中找唯一函数起点。
2. 模式缺失或歧义时，取基准调用者，按同样方式唯一匹配调用者，比对同序号指令形态后读调用目标；全部票一致才采用。
3. DATA只用引用者共识，结果必须落在可写节。
4. 无`.pdata`的叶函数（如`achievement.eligible`）不能用函数起点检查，允许共识结果为不在任何unwind范围内的执行地址。
5. SLOT/TABLE只做静态RTTI检查并报告，与运行时同判据。

不同SHA输出永远`approve.<组>=0`，未解析值写0；同SHA复用原批准，`--rescan`强制重扫用作自检。
复核标记：`SINGLE_ANCHOR`只有一票；`DELTA_OUTLIER`与同组其他候选的位移相差都超过1MB。标记不是失败，是人工优先看的位置。

候选只证明“基准函数形态在目标里唯一出现”，不证明签名、参数布局、所有权或语义不变。批准前仍需xref/调用关系复核与受控验收。

## 新版本流程

1. 以当前已审核映像为基准运行迁移工具，读`migration.json`的`incomplete_groups`与`review`。
2. 逐个确认候选，未解析项用IDA/xref补，手工写入资料并说明依据。
3. 原生夹具`--accept`确认生产加载器接受，再单独把审核过的组改为`approve=1`。
4. 实机受控验收后再部署；未验收组保持0，业务按组门自动跳过。
