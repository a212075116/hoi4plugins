# 类结构验证

> 源码：src/plugin/plugin_main.c 的 VerifyClassStructure / ScanKnownArrays

## 目的

静态分析（IDA）恢复出来的类结构如果错了，后面所有基于它的操作都会错。
这个模块用**运行时内存**去比对静态结论。

## VerifyClassStructure

取 *(hoi4.exe + 0x332F260) 作为 CCurrentGameState*，读它的前两个虚表指针，
与静态 RVA 比对：

| 项 | RVA |
|---|---|
| 全局单例槽 | 0x332F260 |
| ??_7CCurrentGameState@@6B@ | 0x2721158 |
| ??_7CCurrentGameState@@6B@_0 | 0x27211B0 |

实测输出：

    [verify] obj=000002A4655D4F40 vt0=00007FF6F63E1158 vt8=00007FF6F63E11B0 match=2/2

0x7FF6F63E1158 - 0x7FF6F3CC0000 = 0x2721158，与静态 RVA 一致。

**这是整个工程的"地基检查"**：它通过，才说明 IDA 里的类是真实的。

## ScanKnownArrays

在 CGameState 对象内以 8 字节步长扫描 {ptr, size, capacity} 三连，
把 ptr 指向的数组元素与已知虚表比对。

已知类虚表 RVA：

| 类 | RVA |
|---|---|
| CCountry | 0x27E7360 |
| CState | 0x2936CC0 |
| CProvince | 0x2971B18 |
| CCharacter | 0x297EA60 |
| CArmy | 0x295A2B0 |
| CUnit | 0x29530D8 |
| CDecision | 0x27EB3D0 |
| CEffect | 0x27D4990 |
| CTrigger | 0x27D55F0 |

## 防御措施

扫描里"看起来像指针的 8 字节"绝大多数不是真指针。直接解引用会访问违例，
**而且死在我们自己手里，排查时会误以为是游戏的问题**。

所以每次解引用前先 VirtualQuery 确认这一页确实可读。
只查上界不够：地址落在用户态范围内也可能完全没有映射。

该检查已提取为公共函数 ConsoleCmd_IsReadable。
