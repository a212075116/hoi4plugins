# 基础内存检查与借用名称视图

2026-10-14，源码规范化第七批。将通用内存检查从console命名空间移到common，并统一Effect/Trigger的16字节名称view声明。
不改变游戏RVA、注册对象布局、scope、分配器或字符串释放规则。

## 当前Interface

| 文件 | Interface/用途 |
|---|---|
| `common/native_memory.h/.c` | `NativeMemory_IsReadable(address, bytes)`，Windows本进程单区域可读范围检查 |
| `common/native_name_view.h` | `NativeNameView { const char* data; unsigned long long size; }`，借用名称字节视图 |
| `console_cmd.c` | 旧 `ConsoleCmd_IsReadable`入口保留，转发到common，已有调用方无需全部迁移 |
| `effect_reg.c` / `trigger_reg.c` | 直接依赖common内存与view，不再为这两个基础机制包含console_cmd.h |

native_memory单独ClCompile一次；header提供C/C++链接兼容声明。view只含布局，不引入构造/分配/释放函数。

## 可读检查保留的边界

- NULL地址拒绝，包括bytes=0。
- VirtualQuery失败或不是MEM_COMMIT拒绝。
- PAGE_NOACCESS/PAGE_GUARD拒绝；保持原可读保护位集合，PAGE_EXECUTE单独不当作可读。
- end地址回绕拒绝；范围必须落在本次VirtualQuery返回的同一个region内。
- 两个相邻region即使各自可读，跨界范围仍拒绝；不改成遍历多个region。
- committed/readable地址的零长度检查保持可接受。

地址运算从C指针加法改为uintptr_t无符号运算，避免把任意待检查地址视作合法数组指针来做加法。
查询、保护过滤、回绕和region边界检查的顺序不变，未引入更宽松的范围接受规则。
这是瞬时可读性检查，不是写权限、对象类型、生命周期或并发安全保证；之后内存仍可能被释放或改变保护。

## 借用view不等于拥有字符串

原Effect一处、Trigger两处局部NameView均是data指针+64位字节长度，现用同一NativeNameView。
静态检查保持64位指针、sizeof16、data偏移0、size偏移8；Effect的len字段名统一为size，字节布局不变。
它不持有capacity，也不拥有或复制字符串，不负责终止零、验证或释放；调用方仍保证数据在原生调用期间存活。
Trigger临时名字先借用view调用contains，再按原顺序调用原生FreeString，未提前释放。

第八批已共享[32字节形状与data选择](原生字符串布局与调用策略.md)，仍不合并赋值/释放策略。console的CmdString是32字节SSO/指针+size+capacity结构；原生assign/append/释放依赖游戏分配器。
不会因“都是字符串”而把CmdString与16字节view合并。
Effect/Trigger名称验证规则、tooltip清输出和释放条件并不完全一致，本轮只统一确实相同的布局声明。

## 证据与限制

三个原注册器的表达式/控制流/RVA/所有权路径不变，仅基础检查函数/header和view声明/字段名迁移。
13342条虚拟region输入三态符合独立oracle，另外14条检查使用实际VirtualAlloc/VirtualProtect。
720条实际Effect token适配输入验证data指针借用、字节长度与失败时输出状态；Trigger/typed/tooltip与console17项回归也通过。
“实际页面”仅指夹具自身进程内的内存，不代表HOI4指针存活、跨进程权限或GUI验收。
运行与证据见[SDK基础机制回归](../../test/docs/sdk_primitives.md)。
