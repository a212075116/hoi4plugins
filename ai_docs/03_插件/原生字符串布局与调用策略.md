# 原生字符串布局与调用策略

2026-10-14，源码规范化第八批。common统一32字节字符串形状、原生assign声明/RVA与只读data选择，不合并不同调用策略。

## 布局和Interface

| 项 | 当前约定 |
|---|---|
| `NativeString` | union16、size_t size、size_t cap，x64共32字节，offset16/24，pack8 |
| `CmdString` | 原名字保留，成为NativeString的typedef别名，字段与命令/结果布局不变 |
| `NativeStringAssignFn` | 统一原console/存档两处完全相同的原生函数指针声明 |
| `NATIVE_STRING_ASSIGN_RVA` | 同一0x129CA0地址，值不变；不新增版本探测或可读性策略 |
| `NativeString_Data` | 调用方已保证合法32字节字段；cap<=15选内联buf，否则选ptr；不验证、不复制、不释放 |

布局用静态检查确认32字节、64位指针、size/cap偏移16/24。
只读选择用于Effect两处与Trigger两处原本完全相同的SSO/指针表达式。
原有长度门槛、NativeMemory检查、append、临时值释放和调用顺序仍由原函数决定。

## 形状不代表所有权

32字节字段可以指向拥有的游戏分配器内存，也可在原生解析调用中临时借用数据。
因此NativeString不是新增拥有对象，不提供析构、通用free或自动初始化；不能只因cap>15就释放某个临时借用字段。
16字节NativeNameView仍独立，表示data+长度，不新增capacity。
不以游戏的字符串布局描述CRT std::string，也不用CRT free释放游戏内存。

## 控制台与存档策略仍不同

| 条件 | 控制台消息/注册字符串 | 存档文件名字段 |
|---|---|---|
| 空字符串 | 保留允许 | 保留拒绝 |
| 长度 | 原有短串/长串路径 | 1..120字节 |
| 缺模块 | 回退到最多15字节短串 | 长串失败且不改字段 |
| 原生assign地址检查 | 保留原未增加检查的路径 | 仍要求地址可读16字节 |
| 短串写入顺序 | size/cap先更新再复制 | 数据/终止零先复制再更新元数据 |

不同写入顺序在源数据与目标元数据别名时会产生可观察差别；本轮没有将它们合成同一个赋值函数。
ConsoleCmd_SetMessage对cap=0的预初始化、ok保持、NULL参数，以及save helper失败时保持字段的行为不变。
loadgame路径检查、加.hoi4后缀、loader选择与实际载入函数未改写。

## tooltip释放规则没有一起改

Effect与Trigger的out清理、长度限制和临时值生命周期不同，不因共用data选择而统一。
Trigger_FreeString的4096字节对齐/原生释放路径保持原样；没有新增Effect释放、缩容或全字段清零。
此批不是内存泄漏、分配器或异常所有权修复，相关问题需要独立证据和验收。

## 证据

2160条三态输入比较整个32字节字段、返回值、ok、模块/可读性/assign调用次数和长度；包含别名、15/16与120/121字节边界。
其中112条data选择有独立期望，确认不因size/cap异常而额外验证或改字段。
三态字节输出一致，注册器与tooltip回归通过；原生assign和分配器由模型替代，不是游戏实机验证。
