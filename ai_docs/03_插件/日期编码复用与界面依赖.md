# 日期编码复用与界面依赖

2026-10-14，第十二批行为保持整理。目标仍是全项目规范化，本篇只记录日期部分的新进展。

## 已执行的简化

- `GameDate_SetFromText`保留全部文本及年月日时校验，改为调用已有 `GameDate_EncodeParts`，删除重复公式、月份累加循环和三个局部变量。
- `GameDate_EncodeParts`本身不变；设置入口仍调用 `GameDate_SetRaw`，派生字段同步及UI刷新次序不变。
- `gamedate.h`不再包含 `console_cmd.h`，14个函数声明及常量不变；只包含日期头文件即可编译公开接口。
- `gamedate_ui.c`改用基础层 `NativeMemory_IsReadable`，不再依赖console头文件；原兼容入口本就直接调用该基础函数，8字节检查、失败丢弃panel的顺序不变。
- 日期/UI实现移除未使用的载体头文件依赖，不改变初始化、hook、分配器或对象所有权。

未增加转发函数或新的日期表示，也没有搬动函数实现位置。

## 调用约束

编码按现有365天年及固定月份表计算，不新增闰年规则。
文本入口校验年份1..9999、月份1..12、日期1..该月天数、小时0..23，然后复用编码函数。
`GameDate_EncodeParts`是低层计算函数，不自行校验参数；调用者仍必须提供合法月份/日期及可表示的算术输入。
`GameDate_SetRaw`继续写raw、同步派生字段、尝试立即刷新已捕获的UI；没有panel时不把UI刷新失败升级为写日期失败。
UI panel仍是借用指针，可读性检查不等同于完整对象生命周期验证；本批没有新增线程或更改刷新线程。

## 没有强行合并的部分

`GameDate_ReadParamText`仍保留原代码：先检查参数地址8字节，再读取size/cap，再校验size，最后选择数据地址并检查源长度。
不强行改用稍后读取cap的字符串getter，也不把整对象验证、截断策略或读取时序改成console参数策略。
这些是不同的输入约束，不因为结构看起来相似就合并。
四个加时间命令的薄适配仍保留：console回调只有两个参数，需要分别绑定unit和命令文本。
