## 基线失败与修复

| 失败类别 | 原因与修复 |
|---|---|
| 读档后 7 项算术失败 | 全局名字表重启后为空。改为解析当次变量容器并只读验证完整三分量 |
| 同名跨国家 2 项失败 | 原版 set 在别国注销了全局同名登记。身份判定不再依赖这个名字表 |
| 32/33 字节主名 2 项失败 | 主名读取、辅助槽和登记长度不统一。主名上限统一为 33 字节，辅助槽上限 40 |
| 登记容量相关 89 项失败 | 第 128 个名字后不再登记。名字表现在仅用于诊断，容量不决定是否执行 64 位运算 |
| 正上限加最小单位回绕 | 在相加前判断范围，乘除使用 128 位中间量并在有符号转换前限制商 |
| clear 后仍显示大数 | 只清了主槽。拦截原版 clear 的执行体，同时清同容器辅助槽和挂账 |

原生属性测试另发现 INT64_MIN 与零做加/减时没有收敛到对称下限，已补齐。
32 位混算的挂账记录改为按容器和名字共同识别，且按需扩容，不再受固定 64 项限制。

## 身份核验不创建变量

`Var64_Container` 使用游戏函数 RVA `0x542500` 解析 CScopedVariable 的实际容器。
签名由 IDA 静态反编译确认，并在事件中对两个国家的容器及查表结果动态核对。
`Var64_IsStored64` 要求同容器内主槽、高位槽、小数槽全部存在，且编码完整：

- 主槽和高位槽须是精确的整数分量，处于有符号 int32 范围；
- 小数槽 raw 须为 SLOT_SCALE 的整数倍，编码分量在 1..199999 内；
- 缺失或非整数编码返回原版路径，不调用创建槽的地址查找器；
- 读取不向全局名字表登记；名字表只保留写入侧诊断用途。

原有只读查表函数把首节点的探测距离误当作固定桶长度。
按原版 Robin Hood 规则逐节点检查距离后，碰撞链增长的原生夹具通过。
语言桥接同时拒绝非整数分量，避免把普通的 1.5 辅助槽误读成编码标记。

辅助槽命名空间 `_var64h` / `_var64f` 是保留元数据，不应独立写入或删除。
三分量合法性核验不是不可伪造的所有权凭证；刻意构造完全相同的编码无法与真实变量区分。

## 原生夹具、回滚与证据

身份夹具从实际源码提取读取/身份函数，使用受控容器替代游戏容器解析器；
引擎解析器本身另有游戏动态证据，不把 mock 测试称为游戏集成测试。
相同 8 项输入：BASELINE 2/8、退出 1；MODIFIED 8/8、退出 0；ROLLBACK 2/8、退出 1。
回滚作用于独立 `.stress.c` 副本，恢复哈希与 0d24c95 工作树基线一致；没有回退活游戏。

运行游戏测试：`python -u test/modules/effect/stress_variable64.py PHASE --extended`。
它会重启游戏、部署现有构建产物、写独立事件、保存 v64stress 并重启读档。
PHASE 必须是新的报告阶段名，防止覆盖已有证据。它不负责构建 DLL。
只读重查：`python test/modules/effect/stress_variable64.py final --verify-only`。

Evidence：`test/reports/20261012_variable64_transaction/stress/` 下的各阶段日志、
事件文件、expected.json、comparison.json、原生夹具输入/输出，以及 IDA/动态探针记录。
Finding：身份/容量/作用域/上限/clear 缺陷已在所列输入下修复。
Path：保留基线红灯，原生回滚重现，最终游戏与属性测试均绿灯，再提交修复。
四角色仍为该事务根目录的 MODIFIED_FILE.zip、DIFF_FILE.patch、VERIFICATION.txt、ROLLBACK.sh。

## 性能与剩余边界

单次 2560 操作事件耗时：基线约 1.91 秒，最终约 3.56 秒。
该数值包含插件逐操作文件日志、游戏执行和宿主轮询，不是纯算法耗时或 FPS 测量。
已有可见开销增加；后续应分析解析/日志开销，而不是贸然缓存失效的槽地址。

本轮未覆盖：跨作用域前缀操作数、trigger/数组/temp/随机赋值、旧后缀迁移、
挂账跨存档持久化、原版 round/modulo 接入、专用 `_64` effect 的全部极值、
热读档后的容器生命周期、多线程/多人、长时间推进及 UI FPS。
