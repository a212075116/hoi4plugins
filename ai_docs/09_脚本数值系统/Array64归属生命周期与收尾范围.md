## 归属标记与包装记录

array64_ownership_gate.c增加ExportOwned/ImportOwned，包装此前无指针基线记录。
每组八个原生标量：__v64o_NAME_b0..b3为分支身份，__v64o_NAME_i0..i3为组incarnation（某一次创建的身份）。
各分量是1..2147483647的整数，存储raw乘100000，避免已查证的signed32最小值文本保存问题。
测试宿主生成四个随机31位正整数作为一项身份；新建组必须分配新的incarnation，不能沿用旧名/旧世代当身份。
分支转换必须由可信控制器显式换身份；模块不是自动检测任意游戏Save As/复制文件的系统。
标记缺失、小数、0、负或超限都拒绝，不能用默认0掩盖归属不明。

包装文件明确little-endian：magic A64OWN02、包装版本1、内层字节数、八个uint32身份分量、内层A64BASE2记录和外层FNV64。
固定外层开销56字节；内层仍是记录版本1/数值协议2。版本分别检查，不保存进程指针。
导入比较当前原生归属标记后才进入原本scope/lineage/世代/形状验证。
原始未包装基线不会作为fallback接受；之后的公开恢复入口必须走此门控，不能暴露旧诊断导入作为旁路。
FNV与文件SHA256用于意外损坏核对，不是抵抗恶意重算校验的身份认证；标记管理者必须可信。

## 导出前的额外校验

发现并补上了一个边界：有效旧快照也可能在导出时已经不再对应当前组。
ExportOwned现在要求当前完整组的世代、长度和全部原始分量与快照完全一致，才绑定当前归属导出。
否则返回-16，不允许把旧数据盖上当前组的新身份；不是仅检查快照自己的校验和。
原生夹具先复现stale_export_refused失败（210项中209通过、退出1），修正后210/210通过。
失败保留在array_ownership/unit_stale_export，不算通过。最终补充同世代但原始分量已改变的拒绝用例。

| 包装门控返回 | 含义 |
|---|---|
| 1 | 包装通过，导入建立当前会话快照；尚未恢复写入 |
| -10 | 侧车不存在/为空，不回退到缓存记录或猜修复 |
| -11 | 非包装格式或未知包装版本，包括旧原始文件 |
| -12 | 包装长度、校验或身份分量损坏 |
| -13 | 当前归属标记缺失或无效 |
| -14 | 分支不匹配 |
| -15 | 组incarnation不匹配 |
| -16 | 导出快照已不匹配当前合法组 |

内层原有拒绝状态仍保留。拒绝导入使输出快照失效且不调用写适配器。

## 五scope的真实生命周期验证

本国、另一国、州、角色、global各五个独立fixture组，共25组。
先保存包装基线文件，再分别执行：

1. good：相同归属，重启后正常导入并恢复。
2. foreign：显式修改原生分支标记，旧记录拒绝。
3. missingstamp：原生clear_variable删除incarnation标记，拒绝。
4. recreate：原生clear_array/clear_variable实际删除三列与清单，再用同名、同长度、同起始世代重建，分配新incarnation。
5. nofile：从指定查找路径移走侧车（保存独立.removed证据），重启后仅按缺失处理，不用manifest缓存hex补回。

随后故障隔离、savegame aog、新文件确认、退出重启。25组均重新解析原生容器。
good五组恢复为gen4/原值；其余20组维持隔离，拒绝时容器头和桶表观察字节逐字不变、无适配器写入。
同名scalar64=12345678901.125和原版数组[2.5,7.75]保持，测试重建只作用于保留组，未碰同名对象。
独立Python核对25个包装文件（缺失路径的证据副本另读），以及内层scope/name/世代与校验和。
这是控制器显式身份转换与恢复门控验证，不是自动识别任意用户分支、删除重建或所有对象类型。

原生夹具执行同一C源码，另覆盖旧格式不得fallback、坏包装、非法标记、导出陈旧快照、64轮导入恢复和4096元素记录。
最终MSVC /W4编译无警告，stderr为空、退出码0，211/211断言通过；模拟布局与游戏证据分开记录。
游戏131/131检查通过，包含25个独立包装文件oracle；write50个、reload25个样本，相关解析错误0、游戏存活。
重载仅5个good组执行35次恢复槽写入；其余20组拒绝且无写入。
