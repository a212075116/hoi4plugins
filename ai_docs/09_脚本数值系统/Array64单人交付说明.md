# Array64 单人交付说明

当前提供的是正式插件中的显式Array64：10个effect与1个block trigger，以及带保守归属检查的显式恢复。
适用范围为已验证的HOI4 1.19.3 x64单人测试环境；不是多人兼容或无限压力保证。

## 作者最短用法

```text
create_array64 = { var = example value = 0 }
append_array64 = { var = example value = 12345678901.125 }
set_array_element_native = { var = example^0 value = 2.5 }
set_array_element64 = { var = example^0 value = 12345678901.125 }
if = {
    limit = { check_array64 = { var = example^num value = 1 } }
    log_array64 = { var = example^0 value = 0 }
}
```

只在目标组不存在时create；重复create是碰撞，不是隐式重置。clear删除整个专属组，可随后重新create。
元素索引从0开始；^num用于长度比较。名称1..20字符、首字母小写，后续仅小写字母、数字、下划线；最大4096元素。
追加/插入/写入使用value；create/resize使用非负整数长度，扩展元素初始化为0。
set_array_element_native与set_array_element64明确决定最后写入的精度模式；原版set_variable不承担Array64的精度切换。
原版同名标量、原版数组和显式Array64保持独立，旧set_variable64对原版数组索引仍拒绝。
其余完整接口、scope、比较token和错误状态见[脚本接口首轮接入](Array64脚本接口首轮接入.md)。

## Scope与错误处理

已验证ABY、ARI、州335、角色ABY_Hoshino和global，按原版变量容器解析目标；没有另加国家scope限定。
其他scope对象不因这五类通过而自动成为已验证对象；动态/临时/复合数组目标不要作为本接口用法。
ROOT scalar64右操作数已在接口首轮验证；不要把它扩大解释为全部scope前缀/链组合验收。
目标容器可解析时effect结果写__v64sys_status，global用global.__v64sys_status；非0必须按失败处理。若容器无法解析则仅有错误日志，状态槽可能仍是旧值；还需核对脚本解析/注册与本次日志，不能单凭旧0认定成功。
check_array64缺失/隔离/无效读取返回false，不猜作0，也不修改status。

## 存档与侧车备份

侧车路径是游戏根reports/array64_journal/<容器身份>/<逻辑名>.a64j，不接受脚本指定外部路径。
应在暂停、没有继续执行Array64操作的同一检查点，备份游戏存档及相关array64_journal目录；备份完成后再继续操作。
当前每对象只保留最近意图；继续运行会替换最新侧车，因此只有旧存档而没有其配对侧车，并不保证恢复可用。
复制存档/文件夹不能自动识别为新的分支。归属、incarnation、nonce和__v64sys_id都是保留字段，不能手工覆写来强迫恢复。
健康数组不需要每次读档都无条件recover；恢复失败可能是旧存档与最新意图不配对，而非健康数组损坏。
如确需恢复，应保留原文件和失败日志，仅使用相同检查点的可信配对备份；没有配对依据时不要补造侧车或基线。
文件刷新/替换与游戏存档不是联合原子提交，备份策略降低风险但不能替代崩溃/掉电验证。

## 仍需真人/后续发布验收的项目

- GUI悬停与中文结果词视觉：当前工具只开放浏览器，未开放游戏原生窗口。需支持的原生UI访问或用户截图。

- 多人：需协调各端插件/模组版本、操作排序、随机身份、侧车读写、存档校验和、断线重连与保存恢复；目前不承诺可用。

多人测试至少安排主机+客户端，在相同模组场景下比较完整值、长度、generation与结果，而不只看画面。
另测一端侧车缺失/不可写/旧版本、同步操作顺序和重连；记录各端输出，不能因为单人通过就直接用于正式联机存档。
当前可交付边界是“显式单人功能与已列有界恢复/压力验证”，不是“所有发布风险已消除”。
最新结果、资源观测与临时文件残留注意事项见[真实中断与定时持续运行验收](Array64真实中断与定时持续运行验收.md)。中断后的孤儿.tmp尚无自动清理功能，不能删正式侧车来清理。
