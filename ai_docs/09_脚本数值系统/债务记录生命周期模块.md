# 债务记录生命周期模块

2026-10-14，源码规范化第五批。报告目录沿用本批启动时的20261013名称，不迁移已绑定的基线和证据路径。
债务记录的类型、进程内表和生命周期实现集中到 `variable64_debt.inc`，运算与容器解析仍在原位置。

## 现有Interface保持

| 函数 | 原有职责 |
|---|---|
| `Var64_FindDebt` | 用当前container指针和变量名查找第一个active匹配记录 |
| `Var64_NewDebt` | 取第一个inactive槽；必要时扩容，再初始化一条记录 |
| `Var64_ClearDebt` | inactive、name首字节清零、debtInt/debtFrac清零；container不清零 |
| `Var64_ResetDebtForSet` | 只清当前container中第一个同名active记录 |

这些private函数和调用顺序保持，不增加公共Interface或DLL导出。
`.inc`由variable64.c包含一次，工程里作为None项展示，不单独ClCompile。

## 查找和创建不能强行合并

Find在name为NULL或容量为0时不调用container解析；New在检查NULL name之前已经解析container。
New不是GetOrCreate：直接调用可以创建同owner/name的另一条记录，Find仍返回第一条active匹配。
已有调用方的Find后New流程没有重写，避免改变解析次数、重复记录和失败顺序。
没有新增owner缓存或用国家tag替换container指针。

## 容量与内存规则

原私有宏 `VAR64_DEBT_MAX` 名称会误导维护者以为64是硬上限，现改名为 `VAR64_DEBT_INITIAL_CAPACITY`。
值仍为64，之后按原规则翻倍，没有新增最大记录数限制。
首次使用HeapAlloc，扩容使用HeapReAlloc，均保留HEAP_ZERO_MEMORY。
失败时只记录原日志，原table指针、容量和内容保持；不能提前更新容量或清掉旧表。
清理一条记录不缩容、不释放整表，进程生命周期内继续复用第一个inactive槽。
扩容可能移动整表，不能跨New调用保留借用的记录指针；本轮未改写现有调用方的指针生命周期。

## 清理不能简单改成memset

Clear只清name[0]，不清其余name尾部、container或padding；这些字节的旧行为也保持。
New的active设置、strcpy_s、container与数值初始化顺序相同。
没有把旧清理扩展成跨容器、全表或读档时全局清理，也没有新增持久化/epoch匹配规则。
记录身份是进程内container指针加名字，不是可跨存档或跨进程的稳定身份承诺。
