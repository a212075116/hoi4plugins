# 数值显示与侧槽命名模块

2026-10-13，第二批行为保持重构。只整理纯文本计算和侧槽名称生成，不改变游戏变量读写、scope、hook或存读档行为。

## 维护时从哪里进入

| 文件 | 职责 |
|---|---|
| `variable64_decimal.h` | 整数/小数分量转十进制数字、尾零裁剪、精度和小数点移动、文本输出 |
| `variable64_text_format.h` | 修饰符解析、百分比、K/M、正号、静态/动态颜色组合 |
| `variable64_name.h` | 侧槽后缀、40字节完整名称限制、统一构造与原函数适配 |
| `variable64.c` | 原生变量/容器访问、语言桥接、Effect执行、hook安装及载入指令 |

前三者是private模块，以static定义包含到原有单编译单元中，不新增DLL导出，也不改变 `variable64.h` 对外Interface。
采用此方式保留原有函数名、调用顺序和编译器优化方式；不要把这些头文件同时注册为独立ClCompile源。
工程编译清单与VS筛选器已同步。

## 名称生成合并

`Var64_MakeHighPartName` 和 `Var64_MakeFracPartName` 保留原Interface，内部统一调用 `Var64_MakePartName`。
统一机制负责非空检查、完整名称长度、输出容量及包含终止零的复制。
当前后缀 `_var64h` 和 `_var64f` 均7字节，因此主名最多33字节；完整侧槽名称最多40字节，输出容量另需包含终止零。
失败时不写输出；NULL输入/输出、空名字、超长名字及容量不足均维持原行为。

语言桥接中路径复制、侧槽名构造及原生解析调用仍保持原样；本轮不改变这些调用的失败顺序。

## 显示算法不变

十进制与格式化函数体直接迁移，没有改用浮点数或CRT数字格式化。
小数位上限5、格式文本缓冲96、`VAR64_SECTION_SIGN=0x11`均保留。
整数/小数符号、尾零、小数位截断、百分比、SI单位和颜色修饰符的处理顺序不变。
缓冲容量过小的返回行为，以及未写区域保持原值的行为，纳入逐字节对照。

`variable64.c` 从2241行降为1974行；减少的是主文件混杂职责，不意味着267行功能被删除或运行效率已有提升。

## 第二批没有合并的近似实现

第三批已在[字段共享模块](名称字段读取与原生语言桥接.md)中共享目标复制机制，仍保留下述size/size+1与日志差别；不是把两个入口的全部规则合成一个。

- `Var64_ResolveGameVariableEx` 的名称读取检查可读size字节；`Var64_ReadNameOnly`检查size+1字节，并且失败日志不同。不能仅因结构类似强行合并。
- `Var64_LangResolveSlotValue`使用借用字符串字段和本地化上下文；`Var64_ResolveAddressByName`临时替换原生实例字段并恢复。所有权与失败路径不同。
- 存储解码、债务、容器归属、最后setter规则及算术hook没有改写。
- 原版/Array64持久化、事务、generation和落盘顺序完全未动。
