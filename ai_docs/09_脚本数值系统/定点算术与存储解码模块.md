# 定点算术与存储解码模块

2026-10-13，源码规范化第四批。纯定点计算集中到 `variable64_math.h`，容器访问仍留在原位置。
不改变数值精度、scope、最后setter、债务、存读档和恢复顺序。

## 小Interface与职责

| 函数 | 输入/行为 |
|---|---|
| `Var64_CalculateRaw(a,b,op,out)` | 有效ADD/SUB/MUL/DIV操作码、非NULL输出；成功写raw，除零返回0不写输出 |
| `Var64_SaturatingAdd/Sub` | 原有对称饱和规则，函数体直接迁移 |
| `Var64_DecodeStoredParts(lo,hi,frac,outRaw)` | 原生槽值的结构验证与可选取值；失败不写输出 |
| `Var64_ReadStoredIn` | 原容器按frac/high/main查询与提前拒绝，再调用纯解码 |

前三个是private计算函数，不查询容器，不读取/写入游戏内存，也不分配或释放内存。
头文件按原单编译单元包含，不增加DLL导出或新公共Interface。
运算使用MSVC x64整数intrinsics，不改成double。
有效操作码由原有调用方选择；本轮没有扩展为接受任意外部操作码的通用函数。

## 集中常量，不混淆单位

SLOT_SCALE、FRAC_SCALE和FRAC_BIAS目前都是100000，但各有原生槽编码、五位定点精度、分量标记偏置的不同职责，仍保留各自名称。
32位分量上下界、TRUE_CLAMP与四个操作码集中到同一private模块，值保持不变。
不能因为数值相同就把不同单位合成一个含义不清的常量。

## 两种溢出规则不统一

算术结果继续限制到 `[-9223372036854775807, 9223372036854775807]`，溢出饱和。
存储取值则允许完整signed64范围，包括最小值 `-9223372036854775808`；无法表示的元数据拒绝取值，不夹到边界。
邻界整数与反向fraction抵消的处理直接迁移，避免中间乘法溢出；结果与原实现一致。
NULL outRaw是原有“仅身份结构检查”模式：仍验证分量结构，不执行最终raw范围检查。
公共 `Var64_ReadStoredContainerRaw`仍拒绝NULL输出；可选输出只属于内部Interface。

## 查询顺序与失败路径

1. 保留侧槽名生成与container校验。
2. 查询frac并校验标记/整槽值，不通过时不查high/main。
3. 按high、main顺序查询，不擅自批量读取或提前缓存。
4. 将已读取的三个值传给纯解码。

纯解码也验证frac，使独立调用仍有完整结构检查；父函数保留提前检查，是为了保留原查询/拒绝顺序，不是重复的游戏内存读取。
债务归属和容器定位没有搬进计算模块，也没有把身份检查改成无条件完整取值。
