## 已实现的最小闭环

输入为原版scope现场解析的容器、逻辑名、索引、期望世代、signed raw64、wide模式和诊断故障阶段。
wide=1采用v2高低分量及转义kind，wide=0遵循此前原生模式保存范围并清零hi/kind。
只有完整合法组、有效索引、匹配世代且gen<=2147483644才能进入；拒绝不会创建键或推进世代。
不创建组、不改变长度、不移动索引、不处理插入删除清理，不接受已隔离或损坏组作为写入目标。

先快照目标元素lo/hi/kind原始槽，再依次执行五个阶段：

1. gen从偶数g变成g+1，进入奇数隔离态。
2. 写lo。
3. 写hi。
4. 写kind。
5. gen提交为g+2，再用完整只读解码器核验。

每次写之前确认键已存在，写后读回精确raw；不通过浮点数传递。
失败时先确保奇数世代，补偿三个原始槽，全部成功才恢复原始偶数g。
任何数据补偿失败均保持奇数；即使数据已补回但偶数发布被注入失败，也保持隔离。
补偿后必须再用整组读取器确认；出现非目标元素异常时，不覆盖外来数据，重新保持隔离。

| 返回 | 意义 |
|---|---|
| 1 | 已提交且读回一致，gen=g+2 |
| 2 | 未提交；原始值和世代恢复（包括首阶段未改动） |
| -1 | 输入、组、索引、世代或原生模式范围拒绝 |
| -3 | 补偿未完成或整组校验失败，奇数世代隔离 |
| -4 | 连隔离标记的读写/发布都无法确认，严重后端错误 |

-4不能报成“已安全恢复”或“保证隔离”；未来宿主必须停止该对象操作并显式报告。
这不是原版引擎提供的原子事务：仅在同步游戏线程、没有并发修改的现场成立。

## 原生适配器与所有权范围

诊断Frida CModule执行同一C源码，tx_write_existing适配器先做只读查找并确认已存在槽。
随后通过已查证RVA 0xBC5C10与{名字指针,长度}取槽地址，要求与只读查找地址相同，才写signed raw。
这是已存在原生变量存储槽的更新，不是新effect注册，也不等于完整set_variable解析/执行兼容。
0xBC5C10本身可能在缺失时创建槽，因此仅靠此函数不能当安全只读；适配器禁止缺失键，且假定同步稳定现场。
本轮没有调用原生数组创建/扩容/删除ABI，没有验证并发删除与指针失效。
只能改变目标元素三个raw字段和gen；版本、长度、邻居、表桶/字符串及同名原版对象均不是写入对象。
