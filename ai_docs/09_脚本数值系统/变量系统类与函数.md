# 脚本变量系统的类与函数（查证记录）

> 全部条目都带地址，来源是 idalib 静态分析。查到多少写多少，没验证的不写。
> 目标：找到「按名字读写游戏变量」的接口，用于让自建 64 位变量能进存档、能被 log 读出。

## 一、已确认的类（RTTI）

| 类名 | type_info 地址 | 说明 |
|---|---|---|
| `CVariableEffect` | `0x14315f8c0` | 变量 effect 基类 |
| `CSetVariableEffect` | `0x14315fae8` | **`set_variable` 的实现类** |
| `CVariableTrigger` | `0x14316abe8` | 变量 trigger 基类 |
| `CSetVariableTrigger` | `0x14316ac70` | `set_variable` 的 trigger 版 |
| `CVariableResolver` | `0x14317ec18` | 变量解析器（模板实例） |
| `CVariableScriptBase` | `0x14317ec40` | 变量脚本基类 |
| `CBaseVariableEffect<CVariableResolver>` | `0x14315faa0` | 变量 effect 模板基类 |
| `CRandomizeVariableEffect<CVariableResolver>` | `0x14315fa50` | 随机变量 effect |
| `CVariableTrigger@NCareerProfile` | `0x1431771f0` | 职业生涯档案里的变量 trigger |

共 **44 个** `CVariable*` 开头的 RTTI，说明变量系统是模板化的，值类型写死在实例里。

`CSetVariableEffect` 的虚表被两处引用：`0x142bda4fc` 与 `0x142bda560`
（前者是主虚表，后者通常是构造中的第二个虚表指针）。

## 三、变量数据库（`database_scoped_variables`）

断言源路径：`C:\mnt\gsg\hoi4\hoi4_merged\hoi4\source\database_scoped_variables.h`

引用它的 4 个函数：

| 地址 | 大小 |
|---|---|
| `sub_1402EED30` | 314 字节 |
| `sub_1402EEE70` | 275 字节 |
| `sub_1402F05C0` | 942 字节 |
| `sub_14039D1F0` | 1392 字节 |

前两个的核心模式（两者几乎一致）：

```c
sub_140544C90(src, &raw, ctx, 0, 0);      // 读参数
id = raw / 100000;                         // 定点转整数
db = sub_1401774C0();                      // 取 database
obj = sub_14022F740(db, (unsigned)id);     // 按 id 查对象
```

**这证明**：
1. `sub_140544C90` 读出来的值可以是一个**对象 id**（通过 `var:xxx` 或 database 引用）
2. 定点 scale 是 `100000`（第三次独立确认）
3. 变量确实挂在 **database** 上，不是散落在各处的自由哈希表

## 四、相关的字符串（可用来定位更多代码）

| 地址 | 内容 |
|---|---|
| `0x1427404a0` | `invalid database object for effect/trigger: %s %s. use var:var_name to explicitly use variables in effects/triggers` |
| `0x14272bdf0` | `Lists all variables in a scope or for the selected country/state/unitleader`（**存在能列出变量的控制台命令**） |
| `0x14272e698` | `dynamic_variables` |
| `0x142af77f8` | `set_variable`（effect 名） |
| `0x142761440` | `set_variable` 的完整文档字符串（含 `var = ` / `value = ` 与简写形式说明） |
| `0x142af8478` | `Error: Variable "` |
| `0x142af84e0` | `Warning: Variable "`（在 `sub_142072E10`，pdx_lua.cpp） |
| `0x142971d40` | `Variable overflow! Please try fixing this function to avoid such things.`（在 `sub_140E7AFE0`） |

`set_variable` 的文档字符串（`0x142761440`）里说明了两种语法，**这是我们做语法兼容时的依据**：

    set_variable = { num_dogs = 42 }                                  # 简写
    set_variable = { var = num_dogs  value = 42  tooltip = ... }      # 完整
