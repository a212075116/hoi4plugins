# Array64 显式协议设计 v2（当前存储协议与历史模型）

2026-10-12。目标：先确定元素身份、编码与生命周期，不解除现有索引 _64 写入保护。
v2已用于正式Array64接口；v1交互模型仍是历史原型，不等于v2存档验收。使用方式与最新限制见[单人交付说明](Array64单人交付说明.md)。

## 决策：独立存储，不改造同名原版数组

同一个逻辑名称 demo 可以同时存在三类对象：原版标量 demo、原版数组 demo、显式 array64 demo。
array64 只操作自己保留的存储键，前两者完全不动；不再把 array^index 交给标量三槽逻辑。
原版 add_to_array/remove_from_array/clear_array 继续作用于原版数组，不偷偷同步到 array64。
显式 array64 需要专用 API；作者不能直接写保留存储键。任何同名保留键已存在时，创建失败，不覆盖。

首版逻辑名限定 1..20 字节的小写 ASCII 字母、数字、下划线，首字符为字母。
scope 单独通过原版 CEventScope/container 解析，不把 ROOT/global 字样塞进逻辑名或自己猜对象偏移。
保留键：__v64a_NAME_lo、_hi、_kind（原生数组），以及 _ver、_gen、_len（原生标量清单）。
最长键32字节，沿用已确认的安全长度内；这些名字不得使用现有 _var64h/_var64f 标量后缀。
这里32字节指数组基础名；原版实际存储键还追加^num或^索引，最长候选索引键为37字节。
原生存储结构与只读后端见[原生数组只读后端与验证](原生数组只读后端与验证.md)，不是连续vector。

## 元素表示与身份

三列按相同索引存储，每个值都是可由原生 fixed-point 槽存放的 signed int64 raw：

| kind raw | lo raw | hi raw | 含义 |
|---|---|---|---|
| 0 | 原版解析/转换后的原生 raw | 0 | 最后由显式 native setter 接管 |
| 100000..400000 | signed low32(raw64) ×100000，最小分量用0占位 | signed high32(raw64) ×100000，最小分量用0占位 | 最后由 array64 setter 接管，kind记录转义位 |

raw64 直接表示数值×100000；小数已经包含在64位 bit pattern 中，不另建 frac 列。
它与现有标量“整数 hi/lo＋有偏置 frac”的协议不同，必须通过版本2分派，不能混用解码器。
实测原版文本存档将-2147483648写成--2147483648。v2排除此裸分量，kind逻辑值=1+低转义位+2×高转义位，转义位要求对应分量为0。
详见[保留组解码与存档边界](Array64保留组解码与存档边界.md)；此表示仍支持整个signed raw64域，包括LLONG_MIN。
kind0原生模式的lo raw严格限制在(-214748364800000,214748364800000)，hi=0；不把任意raw64当作可保存的原版模式。
native setter 的输入必须是原版转换后的 raw，不凭模型 BigInt 的范围推断原版 set_variable 的全部行为。

元素身份是“解析后的容器、逻辑名、当前索引、当前世代”，不是进程内地址或永久元素 ID。
插入会移动之后的索引，删除会压缩之后的索引；lo/hi/kind 必须作为同一元素一起移动。
旧世代的缓存引用拒绝读取。若以后需要稳定 ID，应另立协议，不改变本版索引语义。

## 清单与事务不变量

1. ver=2；v1及未知版本拒绝。三列长度必须等于len；kind raw只能为0、100000、200000、300000、400000。
2. 完成状态 gen 为偶数；奇数表示提交中/隔离状态，不提供数值读取。
3. 索引表达式只求值一次，随后检查整数、非负和操作边界；插入允许 index=len，设置/删除必须 index<len。
4. 首版模型上限4096元素、gen≤2147483646；达到限制拒绝而不是回绕。这是协议候选限制，不是原版引擎上限。
5. native setter 只改该元素，清零 hi 和 kind；64 setter 只改该元素，重建位分量与 kind。
6. 读取与比较不创建槽、不修改数据。形状损坏、非法分量或未知类型拒绝，不猜补齐或截断。
7. 创建检查全部保留键；清理删除整个专属清单/三列，不清同名原版标量/数组。

模型在暂存副本完成操作，验证后整体提交；注入失败则丢弃副本，原状态完全不变。
游戏后端不能据此假设原生多数组操作原子：必须先快照、标记奇数世代、写三列/清单，最后提交偶数世代。
任何阶段失败都要从快照补偿；补偿也失败则保留奇数世代、隔离并报警，不能把半写入当成有效状态。
本轮未证明原生后端已有可用的原子或补偿 API，所以生产写入仍关闭。

## 插入、删除与保存

插入：三列在同一索引插入同一元素，len+1；删除：三列在同一索引删除，len-1。
按值删除必须在解码值层确定匹配索引集合，再一次事务删除，不在某一分量列单独匹配。
重复值是合法的；原版 remove_from_array 的全部重复值策略尚未确认，不承诺完全仿照它。

游戏持久化候选方案使用原生数组与标量清单的保存机制；不得保存 container 指针、槽地址或 DLL 内缓存。
加载后重新解析容器与保留键，检查版本、世代、长度与元素编码，再允许读取。
损坏/未知快照不迁移、不静默修复。历史模型JSON恢复通过本身不是游戏证据；本轮v2隐藏组另有原生文本保存/退出重启记录，不推广到全部格式。
