## 存储与限制

当前辅助槽名为 `<name>_var64h` 与 `<name>_var64f`，不是旧 `_hi` / `_f`。
整数低位、高位与独立小数构成三分量；效果参数仍受 int64 ×100000 定点范围约束。
旧“只能输出整数”和“每变量只有两个槽”不再是当前实现。
`VAR64_NAME_LIMIT=40` 是底层名字限制，不等于 40 字符主名端到端通过。
主名与辅助槽上限现已统一：主名最多 33 字节（ASCII 为 33 字符），辅助槽最多 40 字节。
本次主名边界用例通过；名字登记表只用于诊断，不再决定读档后的身份或容量。

## 新发现、修复与再验收

输入：`repro_big=92233720368546.05`、`repro_small=1.5`、`repro_neg=-1.5`、`repro_zero=0`。
原文：`REPRO WRITE marker=12026 big=92233720368546.05 small=-1 neg=-1.5 zero=-0`。
`Var64_LangResolveSlotValue` 对所有名字设置 cap=15；辅助槽名超过 SSO 容量时布局错误。
已仅修改 `Var64_LangResolveSlotValue`：短名构造 SSO（含终止符），长名用外部字符串指针和真实容量。指针只借用于同步解析，不转移所有权。

原生 C 夹具覆盖辅助槽名长度 8、16、18、17、39、40，修复后 6/6 通过。原版出现错误布局且 39 字符触发栈保护退出；回滚副本重现原版行为并恢复原始哈希。

游戏修复后 WRITE 与重启读档后的 READ 原文均为：
`marker=12026 big=92233720368546.05 small=1.5 neg=-1.5 zero=0`。
原有 48 个选定断言再跑 48/48，污染为 0。

savegame 探针进程退出码为 0，但命令内部 `out->ok=0`，并返回 access violation。
该失败尝试没有新存档，未把加载旧存档算成成功。随后改用短存档名 `v64repro12`，命令 `out->ok=1` / `Saved`，产生新文件；修改后重新写入用例、保存、退出、仅用 -continuelastsave 重启，再确认 marker=12026 和全部四个值。
