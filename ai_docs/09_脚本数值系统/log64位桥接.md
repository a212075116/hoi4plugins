# 原版 log 输出 64 位变量（语言桥接）

> 历史阶段记录：全文的“本轮/当前/下一步”仅指当时实验，不是最新状态或可直接照抄的实施指令。现状见 [当前状态与复现](当前状态与复现.md)。旧方案、失败与旧偏移保留用于追溯，不覆盖现实现。

> 状态校正（2026-10-12）：三分量已支持真实小数，不能再描述为“小数恒为零”。UI 颜色已由用户在 2026-10-12 明确确认解决，本轮未重新目视验收颜色。
> 当前结论统一见《当前状态与复现.md》；下文保留历史过程，不能作为当前待办清单。

> 上游依据：`log输出链路.md`（log effect 与 game.log 输出链路的静态查证）。
> 本文记录让原版 `log = "[?变量名]"` 直接输出 variable64 完整值的实现与实测。
> 全部地址为 IDA 静态查证 + 运行期实测，未验证处标 ⚠️。

## 一、目标与效果（已实测）

    桥接前:  log = "r07=[?r07]"   ->  game.log: r07=35926.54243   (32 位定点, 值被截断)
    桥接后:  log = "r07=[?r07]"   ->  game.log: r07=92233720368547 (完整 64 位)

原版脚本写法**完全不变**，不需要新的格式化语法。

## 二、hook 点（唯一入口）

| 项 | 值 |
|---|---|
| 函数 | `sub_1412CF2B0`，**RVA `0x12CF2B0`** |
| 引用数 | **2 处**（`sub_1412CED60` 内一处 + 一处数据段）—— `[?...]` 的唯一处理函数 |
| 签名 | `(ctx, text, textEnd, out, depth)` |
| `text` | `'?'` 之后到 `'|'` 或 `']'` 之前的文本（含作用域路径，如 `GER.r07`） |
| `out` | **文本累积缓冲**（std::string*），不是最终结果串 |
| 调用链 | `log = "..."` → `CLogScriptEffect::exec` (`0x1393DF0`) → `sub_1410E48A0` → `sub_1412CED60` → `sub_1412CF2B0` |

## 三、运行期取值方式（实测确认）

`ctx` 是 `CContextLocalizationText`（虚表 `0x1427DE358`），其**虚表 +0x20 槽**（`sub_1410E37E0`）按变量路径解析：

```c
/* 名字写成 std::string（SSO），第二参数是【输出指针的地址】 */
((Var64CtxResolveFn)(*(void**)((char*)vtable + 0x20)))(ctx, &resolved, nameField);
```

**实测：返回的 `resolved` 就是变量槽里的值本身**，不是对象指针：

| 变量 | 解析返回值 | 含义 |
|---|---|---|
| `r07` | `0xD6238DA3` = 3592654243 | 正是 lo（写入时存进主变量的值） |
| `r07_hi` | `0x53E2` = 21474 | 正是 hi |

所以组装式与原实现一致：

    value = ((unsigned long long)hi << 32) | (unsigned long long)lo

## 四、写回文本必须用 append

`out` 是**同一行文本的累积器**（同一行里 `[?...]` 之前的文本已经在里面）。

| RVA | 函数 | 用法 |
|---|---|---|
| `0x129CA0` | `std::string::assign(dst, src, len)` | 覆盖（**不要用于 out**） |
| **`0x129C10`** | **`std::string::append(dst, src, len)`** | **追加（本实现采用）** |
| `0x11D970` | `std::string(const char*, size_t)` 构造 | 造临时串 |

踩坑记录：最初用覆盖写法，结果同一行里 `SETUP marker=... r07=` 这半句被清掉，
game.log 只剩 `92233720368547 r07hi=0.21474`。

## 五、判定"哪些变量是 64 位"

变量名带 `_hi` 的才是我们的 64 位变量，但**不能只靠"高位 != 0"**：
值小于 2^32 时高位为 0，会和"不存在的变量"混在一起。

实现用两级判定：

| 来源 | 说明 |
|---|---|
| **已登记名字表** | `set_variable64` / `add_to_variable64` 成功时登记（`Var64_RememberSixtyFourBitName`） |
| **兜底** | `<名字>_hi` 解析出的值 != 0 时，判定为 64 位变量并补登记 |

命中后：`lo = 解析(名字)`、`hi = 解析(<名字>_hi)`，组装 → append 十进制文本 → 直接返回（不调原函数）。
未命中：原样调用原函数，**原版变量行为完全不变**。

## 七、数字修饰符（已支持，全量实测 25 项）

依据 wiki `Localisation` 的 **Formatting variables** 章节（本地副本第 839~891 行）：

| 修饰符 | 作用 | 实测输出（`r07 = 92233720368547`） |
|---|---|---|
| 无 | 纯整数 | `92233720368547` |
| `0`..`9` | 小数位数，>5 按 5 处理 | `|2` → `92233720368547.00` |
| `*` / `^` | SI 单位（K/M），默认 2 位小数 | `|*` → `92233720.36M` |
| `%` | ×100 并加 `%` | `9223372036854700%` |
| `%%` | 只加 `%` | `92233720368547%` |
| `=` | 正数前置 `+` | `+92233720368547` |
| `+` | 动态色：正绿/零黄/负红 | `§G92233720368547§!` |
| `-` | 动态色：正红/零黄/负绿 | `§R92233720368547§!` |
| 颜色字母 | 静态色（`§X` 开始，`§!` 结束） | `|R` → `§R…§!` |
| 组合 | 互斥取最后；静态色优先级低于动态色；`%%` 覆盖 `%` | `|.1%%+` → `§G92233720368547.0%§!` |

实现函数：`Var64_ParseTextFormat` / `Var64_BuildFormattedText`（源码全 ASCII，`§` 写作 `0xA7`）。
完整 25 项实测见 `test/reports/20261011_0150_插件_variable64本地化数字修饰符_全量验证.txt`。

## 七之二、当前边界与历史结论校正

- 小数恒为零是早期双分量实现的限制；三分量实现已有真实小数输出，本次四则运算也复现了 105.25、2762.5、276.25 等结果。
- 旧的“高位为零无法识别”描述不再准确：语言桥接会读取分数分量，不能仅凭高位判断。最新规则下的完整跨进程往返仍需独立验收。
- 本次发现并修复超过 15 字符的辅助槽名 SSO 布局错误；`repro_small=1.5` 修改前为 `-1`，修改后原版 log 与重启读档均为 `1.5`。原生夹具覆盖到 40 字符辅助槽名，不等于 40 字符主名已通过。
- UI 颜色已由用户确认解决。历史颜色失败报告仅保留失败时的观察，不再列为当前缺陷。
- 语言桥接不在读取时登记变量。当前原版运算按实际容器只读核验完整三分量，不依赖全局名字表；详细规则和保留辅助槽命名空间见《读档身份与抗压验证.md》。
