# Array64 显式恢复与运行时压力

2026-10-12，HOI4 1.19.3 Windows x64。承接固定长度事务；仍不开放公开写入或恢复API。
新源码array64_recovery.c由诊断Frida CModule和MSVC夹具执行，未编入plugin.vcxproj。

## 快照归属与完整性

Array64_Capture只接受完整合法的v2组和匹配的偶数世代，捕获全部元素三列，而非只捕获目标元素。
快照含逻辑名、长度、基线世代、当前容器、调用方owner token、三列、校验和及已消费状态。
Array64_SnapshotBytes返回真实编译布局大小，宿主分配 opaque buffer，不能猜偏移或跨ABI搬运结构。
捕获失败使快照失效，不能悄悄沿用之前成功捕获的旧内容。
恢复时检查名称、当前容器、非零owner token、基线世代、长度、完整性及全部编码。
FNV64校验用于意外损坏检测，不是密码学认证；owner由可信宿主分配，本API不接受任意外部快照作为可信输入。
容器指针和owner token属于当前进程/会话身份，禁止序列化指针后跨重启直接复用。

## 隔离检查与显式恢复

Array64_InspectQuarantine只读确认版本2、合法奇数世代、长度、三列长度、完整键集合及每个槽存在。
允许数据编码因部分写入而暂时非法，但不允许缺键、增删长度、残余键或改变版本。
它不返回“可用数值”，不猜修复；长度/世代输出只在检查成功时更新。

Array64_Recover要求当前odd=快照基线gen+1，长度完全相同，且快照未消费。
在保持奇数隔离的前提下，逐槽写回整组三列，逐次读回核验；最后发布odd+1并再次校验整组。
成功后消费快照。重复提交旧快照、跨容器/名称/token、校验和错误或陈旧基线都在写前拒绝。
恢复失败不消费快照，保持奇数，允许同一可信快照再次显式尝试；不自动重试无限写入。
当最终发布已写入但后端报告失败时，尝试重新隔离；无法确认隔离标记时返回严重错误，不声称安全恢复。
所有操作仍仅在同步稳定游戏线程内成立，检查与逐槽写入不是跨线程原子事务。

| 入口/返回 | 含义 |
|---|---|
| Capture 1 / -1 | 快照有效 / 捕获拒绝且失效 |
| Inspect 1 / -1 / -2 | 完整隔离形状 / 元数据拒绝 / 键与列形状拒绝 |
| Recover 1 | 恢复完成、新偶数世代、快照已消费 |
| Recover -1 | 快照身份、完整性、编码、参数或消费状态拒绝 |
| Recover -2 | 当前隔离形状与基线世代/长度不匹配 |
| Recover -3 | 写回/发布失败，仍处于隔离，快照保留 |
| Recover -4 | 重新隔离也无法确认，必须停止对象操作并报告 |

此版只能恢复“所有槽仍存在、长度未变”的部分写入组，不能恢复创建/删除/变长损坏。

## 真实游戏压力与持久化观察

驱动verify_array64_recovery.py构造独立fixture组，在本国/另一国/州/角色/global同步事件现场执行同一C源码。
每scope分别验证正常恢复、恢复途中失败再尝试、坏校验和/owner/容器拒绝和反复切换。
压力每scope16轮，共80轮：成功更新→捕获新基线→制造补偿失败→确认隔离→拒绝旧基线→显式恢复→拒绝快照重放。
原生2.5与signed raw最小值交替；每轮推进到新偶数世代，16轮后gen=66。
所有非目标元素及同名scalar64=12345678901.125、原版数组[2.5,7.75]都检查不变。
原生适配器与前轮相同：仅确认已存在的槽，调用RVA 0xBC5C10取地址并核对，才写signed raw。
掩蔽允许的目标四个raw字段后比较容器头和桶表其余字节；不把此观察扩大为全进程无写入。
完成恢复后保存新atx存档，退出重启，仅只读确认恢复值、新世代与同名对象。
最终274/274检查通过，write/reload各20个独立scope/组样本；1735次适配器写入保留逐槽前后值。
80轮真实循环全通过，相关fixture解析错误0、游戏存活；非压力组恢复为gen=4，压力组gen=66。
这是恢复结果的持久化，不是快照本身已持久化；恢复动作发生在退出之前。
