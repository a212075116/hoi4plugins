# 模板复用与早期边界（历史证据）

> 本文只保存当轮探索、失败和旧方案，不是当前操作手册。已推翻的布局/名字长度/回绕/两槽假设不得沿用；当前实现见[当前状态与复现](当前状态与复现.md)。

## 二十一、原版语法的实现路线（第10轮 · 关键实验）

### 21.1 目标

让 `set_variable64` 支持与 `set_variable` 完全相同的两种语法：

```
set_variable64 = { 名字 = 值 }
set_variable64 = { var = 名字  value = 值 }
```

### 21.2 实验一：换 entry 虚表

把 `var64_set_a` 的 `entryVt[0]` 换成 `CEffectEntry<CSetVariableEffect>` 的虚表（RVA `0x277C418`）。

结果：单值形式 `var64_set_a = 111` 报错

```
Error: "Non assign effect is not enclosed in {}: var64_set_a"
```

**说明 entry 虚表决定参数形态**（单值 vs 块）。

### 21.3 实验二：再换实例虚表

factory 造 `CSetVariableEffect` 实例（544 字节），并把实例虚表换成我们自己的（25 槽里 24 个取自
`CSetVariableEffect::vftable`，只把 exec 槽 `+0x68` 换成我们的函数）。

结果：exec 被正确调用了，但变量名不对：

```
[v64par] nameField(+200) size=1 ; nameField text = [{]
```

**游戏把块的 `{` 当成了变量名** —— 说明实例虚表也参与块内键的解析。

### 21.4 实验三：entryVt 的 patch 时机

`Effect_RegistryRegister` 内部会重设 `entryVt[0]`：

```c
def->entryVt[0] = *(void**)(img + RVA_STAB_ENTRY_VT);   // 覆盖我们之前的修改
def->entryVt[1] = (void*)def->factory;
```

所以必须在 `Effect_RegistryRegisterAll` **之后** patch。改到之后，patch 确实生效了
（`0x7FF6C63B2FF0` = RVA `0x2E2FF0`），但结果仍和实验二一样。

### 21.5 实验四（决定性）：完全复用游戏

注册一个 effect `var64_gm`，**entry 虚表、factory、实例虚表、exec 全部用游戏的**。

脚本：

```
set_variable = { gmprobe = 0 }
var64_gm = { var = gmprobe value = 555 }
log = "GMPROBE after = [?gmprobe]"
```

输出：

```
GMPROBE after = 555
```

**完全成功，没有任何错误。**

### 21.6 结论

| 项 | 结论 |
|---|---|
| entry 虚表 | 决定参数形态（单值 / 块） |
| 实例虚表 | 决定块内键的解析（换掉就会错乱） |
| **三者必须全部是游戏的** | **entry + 实例 + exec**，缺一不可 |

因此**不能**用一个「换了 exec 的实例」来继承游戏的块解析。

### 21.7 定下的实现路线：MinHook 挂 exec

```
1. set_variable64 的 entry / factory / 实例虚表 全部保持游戏的
   -> 块解析完全正确，变量名进 +200，参数进 +408

2. 在 factory 里给实例打标记（实例 +505 有 7 字节空隙未被构造函数使用）

3. 用 MinHook 挂 CSetVariableEffect::exec（RVA 0x364C60）
   - self+505 有标记 -> 我们的逻辑：
       sub_140542280(self+88, ctx, 0) 拿值地址
       写入完整 64 位
       返回
   - 无标记 -> 调原函数（set_variable 不受影响）
```

### 21.8 CSetVariableEffect 实例布局（本轮更新）

| 偏移 | 内容 |
|---|---|
| `+0` | 虚表（**必须是 CSetVariableEffect 的**） |
| `+88` | **CScopedVariable A** —— 变量名在 `+200`（= `+88 + 112`） |
| `+296` | **CScopedVariable B** —— 参数在 `+408`（= `+296 + 112`） |
| `+504` | byte 标志（exec 据它选分支） |
| `+505`..`+511` | 空隙（可用作标记） |
| `+512` | std::string（data `+512` / size `+528` / cap `+536`） |

构造函数 `sub_14032D260` 只初始化到 `+536`，所以 `+505`..`+511` 是安全空隙。

### 24.2 原版 log 的显示规则（本轮确认）

```
raw = value x 100000
[?var] 显示 = ((raw / 100000) mod 2^32) / 100000
```

即：**先定点还原、再取低 32 位、再按定点（除以 100000）显示**。

实测：

```
VANILLA t5=21474.83648 t8=35926.54243 ta=26665.24672
```

| 变量 | 值 | 低 32 位 | 除以 100000 | 实际输出 |
|---|---|---|---|---|
| t5 | 2147483648 | 2147483648 | 21474.83648 | 21474.83648 ✓ |
| t8 | 92233720368547 | 3592654243 | 35926.54243 | 35926.54243 ✓ |
| ta | 79000000000000 | 2666524672 | 26665.24672 | 26665.24672 ✓ |

**所以原版 `[?var]` 只能给出低 32 位对应的定点数，无法表达完整的 64 位值。**
完整值由 `log_variable64` 输出。

### 24.3 边界行为

| 边界 | 值 | 结果 |
|---|---|---|
| int32 上限 | 2147483647 | 正确 |
| 超 int32 上限 | 2147483648 | 正确（原版 set_variable 此处会变 -2147483648） |
| int32 下限 | -2147483648 | 正确 |
| 超 int32 下限 | -2147483649 | 正确 |
| 定点上限 | 92233720368547 | 正确 |
| 负定点上限 | -92233720368547 | 正确 |
| 超定点上限 | >= 92233720368548 | **会回绕**（int64 溢出，非 bug） |

### 24.4 一个脚本注意事项

事件文件里**不要在 effect 块内写 `#` 行内注释** —— 实测会使事件在注释处中断
（第一版事件 47 带注释，只跑到 t9 就停了；去掉注释后 16 项全部执行）。

## 二十五、边界情况验证（第18轮）

完整报告：`test/reports/20261010_2346_插件_variable64边界情况_验证.txt`
触发：`event zzdatetest.48`

### 25.1 变量名长度（优雅降级）

| 名字长度 | `_hi` 长度 | 高位 | 低位 | 结果 |
|---|---|---|---|---|
| 12（`abcdefghijkl`） | 15 | 写入成功（hi=2874） | 1942892530 | 完整支持 |
| 13（`abcdefghijklm`） | 16 | **拒绝**，日志 `name too long for high part` | 555 | 优雅降级 |
| 14（`abcdefghijklmn`） | 17 | 拒绝 | 777 | 优雅降级 |
| 15（`abcdefghijklmno`） | 18 | 拒绝 | 999 | 优雅降级 |

**名字 <= 12 字符时可完整保存 64 位；13..15 时只保存低 32 位。** 全程不崩溃。
原因：变量名走 SSO（上限 15 字符），加 `_hi` 后不得超过 15。

### 25.2 算术溢出（int64 自然回绕）

| 步骤 | 表达式 | 结果 |
|---|---|---|
| 1 | `set ov = 92233720368547` | 92233720368547 |
| 2 | `ov += 92233720368547` | **-1** |
| 3 | `ov += -92233720368547` | 92233720368547 |

数学验算：

```
9223372036854700000 x 2 = 18446744073709400000
18446744073709400000 - 2^64 = -100000
-100000 / 100000 = -1                     <-- 与实测一致
```

### 25.3 不存在的变量

```
log_variable64 = { var = neverset }   ->   0 (lo=0 hi=0)
```

查表时自动创建，值为 0，不崩溃。

### 25.4 已知限制汇总

| 限制 | 数值 |
|---|---|
| 变量名长度 | 1..15（SSO），加 `_hi` 后 <= 15，**实际可用 1..12** |
| 数值有效范围 | **-92233720368547 .. 92233720368547**（定点 `2^63/100000`） |
| 超出范围 | int64 回绕（不报错） |
| 每个变量占两个槽 | 主变量 + `_hi` |
| 原版 `[?var]` 显示 | 仅低 32 位对应的定点数 |
