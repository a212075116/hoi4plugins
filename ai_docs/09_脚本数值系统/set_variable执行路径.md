## 二、exec 函数本体（关键）

```c
__int64 __fastcall sub_140364C60(__int64 a1, __int64 a2)   // a1=实例, a2=ctx
{
    v4 = sub_140542280(a1 + 88, a2, 0LL);          // 取【变量值的地址】
    v6 = (_QWORD *)v4;
    if ( a1 == -296 || *(_BYTE *)(a1 + 504) != 1 )
    {
        if ( *(_BYTE *)(a1 + 504) ) sub_1403BAAF0();
        sub_140544C90(a1 + 296, &v8, a2, 0LL, 1u); // 读 value 参数, ★ a5 = 1 ★
    }
    else
    {
        sub_14141C290(a1 + 296, &v8, a2);          // 另一种读法
    }
    *v6 = v8;                                      // 【写值】
    return v8;
}
```

**三点结论**：

1. **`sub_140542280(self + 88, ctx, 0)` 返回「变量值的地址」** —— 这就是按名字定位变量的 API
2. **`sub_140544C90` 的第 5 个参数游戏传 `1`，我们一直传 `0`** —— 该参数有语义，需要后续验证
3. **变量值就是一个 8 字节槽**（`*v6 = v8`）—— 这说明存储宽度是 8 字节；
   但写入前会经过定点转换，**语义位宽仍是 int32**（实测 `2^31` 翻负）

## 三、变量地址的解析链

```c
__int64 __fastcall sub_140542280(__int64 a1, __int64 a2, __int64 a3)
{
    if ( *(_BYTE *)(a1 + 14) )
        v6 = sub_14054F730();
    else
        v6 = sub_140542500(a1, a2, &v15, &v14, &v13, &v12, &v11, &v10, &v9, &v8);
    return sub_140542330(a1, v6, a2, a3);      // 最终地址
}
```

相关函数：`sub_14054F730`、`sub_140542500`、**`sub_140542330`（最终返回地址）**。
`+14` 是个 byte 标志，决定走哪条分支。

## 七、变量存储结构（第2轮追加 · 完全解密）

### 7.1 源文件位置

变量系统核心在 `hoi4\source\scopedvariable.cpp`（断言里给出的路径，行号 1430/1431）。

两条断言：

- `IsReadOnly() == false`
- `pVariables != nullptr && "invalid event scope to get variable"`

### 7.2 变量容器定位

`sub_140542330` 里 `v4 = *(_QWORD *)(a1 + 160)` —— **实例的 `+160` 就是变量容器指针**。
（注意：参数 `a4` 非 0 时优先用 `a4`。）

哈希表本体在 **容器 `+16`**（`sub_140BC5C10` 里 `v4 = a1 + 16`）。

### 7.3 查找算法 = FNV-1a 32 位

```c
v7 = -2128831035;                       // 0x811C9DC5  FNV offset basis
do {
    v9 = *v5++;
    v7 = 16777619 * (v7 ^ v9);          // 0x01000193  FNV prime
} while (--v8);
```

就是标准 FNV-1a。**这意味着我们可以自己算 hash，不依赖游戏函数。**

### 7.4 哈希表结构

`sub_140BC3F10(表, 出参, hash, 名字对象, a5)`：

| 表内偏移 | 内容 |
|---|---|
| `+8` | 桶数组基址 |
| `+16` | 元素数（`*(_DWORD *)(a1 + 16)`） |
| `+20` | **桶掩码**（容量-1，`hash & mask` 定位桶） |
| `+24` | byte 阈值（`v7 > *(_BYTE *)(a1 + 24)` 触发扩容判断） |
| `+28` | float 装载因子 |

桶步长 **48 字节**：`v10 = *(QWORD*)(a1 + 8) + 48 * (hash & mask)`。
桶内遍历：`v10 += 12`（12 个 DWORD = 48 字节）跳到下一条目。

### 7.5 条目（节点）结构 —— 48 字节

| 节点内偏移 | 内容 |
|---|---|
| `+0` | hash（4 字节） |
| `+4` | byte：桶内条目序号 |
| `+8` | **std::string 变量名**（SSO 布局：data `+8`、size `+24`、cap `+32`） |
| **`+40`** | **值（8 字节）** |

命名比较逻辑（原文）：

```c
Buf2 = v10 + 2;
if ( *((_QWORD *)v10 + 4) > 0xFuLL ) Buf2 = *(unsigned int **)Buf2;   // cap > 15 走间接
if ( Buf1[1] == *((void **)v10 + 3) && (!Buf1[1] || !memcmp(Buf1[0], Buf2, Buf1[1])) )
    break;                                                             // 名字命中
```

`v10+2`（DWORD）即 `+8`；`*((QWORD*)v10 + 4)` 即 `+32`（cap）；
`*((void**)v10 + 3)` 即 `+24`（size）。

### 7.6 值地址 = 节点 + 40

`sub_140BC5C10` 最后一行就是 `return v11 + 40;` —— **值就是节点内的一个 8 字节字段**。

## 八、完整的调用链（可直接照做）

```
effect 名 "set_variable"
  → token 表 0x14338D170 + 72*index      (id = 10163, index = 1543)
  → _EffectEntries map @ hoi4.exe+0x3330000  (key = id)
  → entry (16 字节: {vftable, desc})
  → entry->vftable[+0x08]() = 工厂 sub_140341F60  (malloc 0x220)
  → 实例 (CSetVariableEffect, 544 字节)
  → 实例->vftable[+0x68]() = exec sub_140364C60
        │
        ├─ sub_140542280(实例+88, ctx, 0)       取变量【值的地址】
        │     └─ sub_140542330
        │           ├─ 容器 = *(QWORD*)(实例+88+160)
        │           ├─ sub_1405454A0(...)      构造变量名 std::string
        │           ├─ sub_140302F00 / sub_140544C90   取索引 id
        │           └─ sub_140BC5C10(容器, {名,长}, id)
        │                 ├─ FNV-1a 算 hash
        │                 └─ sub_140BC3F10(表, &node, hash, 名, id)
        │                       → return node + 40          <<< 值地址
        ├─ sub_140544C90(实例+296, &v, ctx, 0, 1)   读 value 参数 (a5=1)
        └─ *值地址 = v                              【写值】
```

## 九、对实现的意义

**我们现在有两条路可以读写游戏变量**：

| 路线 | 做法 | 优缺点 |
|---|---|---|
| A. 调游戏函数 | 造一个 `CSetVariableEffect` 实例，填好变量名，调 `sub_140542280` 拿地址 | 稳，但依赖实例构造细节 |
| B. 自己实现 | 从容器指针出发，用 FNV-1a 算 hash，遍历桶找节点，取 `+40` | **不需要构造实例**，逻辑已完全掌握 |

**路线 B 更干净** —— hash 算法、桶定位、节点布局都已知，
只需拿到「变量容器指针」，而它就在 `实例 + 88 + 160`。
要拿到容器，可以调 `sub_140542280` 或直接找到当前作用域的容器来源。

## 十一、实测验证（第2轮 · CE 动态）

### 11.1 实验方法

1. mod 事件里设两个变量：

```
set_variable = { dshprobe = 1847293651 }                             # 简写形式
set_variable = { var = dshprobe2 value = 1234567891 }                 # 完整形式
```

两种形式**都成功**（`game.log` 里读回 `1847293651` 和 `1234567891`）。

2. 定点换算：`1847293651 x 100000 = 184729365100000`（8 字节）。

3. 用 CE `scan_all` 扫这个 8 字节值 → **命中 2 个地址**：

```
0x2206B2ECEF8   184729365100000
0x2207EEEA598   184729365100000
```

### 11.2 节点布局实测（第一个地址周围）

以值地址 `a = 0x2206B2ECEF8` 为原点，读 8 字节视角：

| 偏移 | 值 | 解释 |
|---|---|---|
| `-40` | `0x4B81F1142` | 节点 +0：hash（低 32 位 `0xB81F1142`） |
| `-36` | `4` | 节点 +4：桶内条目序号/总数 |
| `-32` | `0x65626F7270687364` | **节点 +8：`"dshprobe"`**（小端 ASCII） |
| `-24` | `0` | 节点 +16：SSO 数据尾 |
| `-16` | `8` | 节点 +24：size = 8（正好是 `dshprobe` 的长度） |
| `-8` | `15` | 节点 +32：cap = 15（SSO 上限） |
| `0` | `184729365100000` | **节点 +40：值** |

`0x65626F7270687364` 按小端拆字节：

```
64 73 68 70 72 6F 62 65
 d  s  h  p  r  o  b  e    => "dshprobe"
```

**与静态分析推断的节点布局逐项吻合。**

### 11.3 FNV-1a 哈希验证

手算（Python）：

```python
h = 0x811C9DC5
for ch in b'dshprobe':
    h = (h ^ ch) * 0x01000193 & 0xFFFFFFFF
```

结果：

```
FNV-1a(dshprobe) = 0xB81F1142 = 3089043778
内存实测节点+0    = 0xB81F1142 = 3089043778
MATCH
```

**哈希算法完全确认，且能自己算，不依赖游戏函数。**
