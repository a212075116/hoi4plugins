# set_variable 的完整执行路径（查证记录 · 第2轮）

> 全部地址来自 idalib 静态分析 + CE 动态读取。查到多少写多少。
> 这份文档是实现「按名字读写游戏变量」的直接依据。

## 一、从 effect 名字到 exec 函数的完整链路

### 1. token 名字表（静态，编译期生成）

| 项 | 值 |
|---|---|
| 表首 | `0x14338D170` |
| 元素大小 | 72 字节 |
| 元素个数 | 10765 |
| 元素布局 | `{int id @+0, byte @+4, 字符串对象 @+8}` |

**CE 实测遍历结果**：`set_variable` 的 `id = 10163`，表索引 `1543`。
（注意 id ≠ index，与文档《注册新Effect》里的观察一致）

### 2. `_EffectEntries`（运行期 `std::map<int, entry*>`）

| 项 | 值 |
|---|---|
| map 对象全局 | `hoi4.exe + 0x3330000` |
| map 布局 | MSVC `std::map`，`_Myhead @ +0`，`root = head->_Parent` |
| 节点布局 | `{_Left @+0, _Parent @+8, _Right @+16, _Color @+24, _Isnil @+25, pair @+32}` |
| pair 布局 | `key(int) @+32`，`value(ptr) @+40` |

**CE 实测**（遍历二叉搜索树找 key=10163）：


### 4. 实例的构造函数 `sub_14032D260`

```c
__int64 __fastcall sub_14032D260(__int64 a1)
{
    sub_14053CFD0(a1);                          // 基类构造
    *(_QWORD *)a1 = &CVariableEffect::`vftable';
    sub_14014AFD0(a1 + 88);                     // 子对象 A
    sub_14014AFD0(a1 + 296);                    // 子对象 B
    *(_BYTE *)(a1 + 504) = 0;                   // 标志位
    *(_OWORD *)(a1 + 512) = 0LL;
    *(_QWORD *)(a1 + 528) = 0LL;
    *(_QWORD *)(a1 + 536) = 15LL;               // SSO 容量 = 15
    *(_BYTE *)(a1 + 512) = 0;                   // std::string 变量名
}
```

**实例布局（已确认）**：

| 偏移 | 内容 |
|---|---|
| `+0` | 虚表 |
| `+88` | 子对象 A（变量目标解析器） |
| `+296` | 子对象 B（参数读取器） |
| `+504` | byte 标志（决定参数走哪条读法） |
| `+512` | **std::string 变量名**（SSO，`size @+528`，`cap @+536`） |

## 二、exec 函数本体（关键）

```c
__int64 __fastcall sub_140364C60(__int64 a1, __int64 a2)   // a1=实例, a2=ctx
{
    v4 = sub_140542280(a1 + 88, a2, 0LL);          // 取【变量值的地址】
    v6 = (_QWORD *)v4;
    if ( a1 == -296 || *(_BYTE *)(a1 + 504) != 1 )
    {
        if ( *(_BYTE *)(a1 + 504) ) sub_1403BAAF0();
        sub_140544C90(a1 + 296, &v8, a2, 0LL, 1u); // 读 value 参数, ★ a5 = 1 ★
    }
    else
    {
        sub_14141C290(a1 + 296, &v8, a2);          // 另一种读法
    }
    *v6 = v8;                                      // 【写值】
    return v8;
}
```

**三点结论**：

1. **`sub_140542280(self + 88, ctx, 0)` 返回「变量值的地址」** —— 这就是按名字定位变量的 API
2. **`sub_140544C90` 的第 5 个参数游戏传 `1`，我们一直传 `0`** —— 该参数有语义，需要后续验证
3. **变量值就是一个 8 字节槽**（`*v6 = v8`）—— 这说明存储宽度是 8 字节；
   但写入前会经过定点转换，**语义位宽仍是 int32**（实测 `2^31` 翻负）

## 三、变量地址的解析链

```c
__int64 __fastcall sub_140542280(__int64 a1, __int64 a2, __int64 a3)
{
    if ( *(_BYTE *)(a1 + 14) )
        v6 = sub_14054F730();
    else
        v6 = sub_140542500(a1, a2, &v15, &v14, &v13, &v12, &v11, &v10, &v9, &v8);
    return sub_140542330(a1, v6, a2, a3);      // 最终地址
}
```

相关函数：`sub_14054F730`、`sub_140542500`、**`sub_140542330`（最终返回地址）**。
`+14` 是个 byte 标志，决定走哪条分支。

## 四、对实现的直接价值

| 需求 | 靠这些地址怎么实现 |
|---|---|
| 按名字读写游戏变量 | 调用 `sub_140542280(target, ctx, 0)` 拿到地址，再 `*addr = v` |
| 让值进存档 | 用上面这条把值写进游戏变量，存档会自己带上 |
| 让 log 能读 | 同上，值进了游戏变量，`[?var]` 自然能读 |
| 与 32 位变量运算 | 同上，游戏自己的运算读的就是这些槽 |
| 语法兼容 | `set_variable` 的语法实现在 `sub_140364C60`，可以照它的模式做 |
