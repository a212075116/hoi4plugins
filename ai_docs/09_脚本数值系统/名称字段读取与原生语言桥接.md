# 名称字段读取与原生语言桥接

2026-10-13，源码规范化第三批。目标是共享正确的字段读取机制，并将原生本地化桥接收拢到一个内部实现片段。
本轮不改变scope、字符串所有权、原生函数RVA或hook安装顺序。

## 当前分工

| 文件/函数 | 职责 |
|---|---|
| `variable64_name_field.h` / `Var64_CopyTargetName` | 目标名称字段的SSO/指针解码、长度限制、数据可读检查及逐字节复制 |
| `Var64_ResolveGameVariableEx` | 模块/实例校验、复合目标日志、字段可读检查；名称复制后保留原生参数与地址解析 |
| `Var64_ReadNameOnly` | 保留无日志的目标校验与终止零可读要求 |
| `Var64_ReadOperandNameAt` | 仍独立处理操作数字段、literal标志、输出清零、176字节descriptor检查与memcpy |
| `variable64_language.inc` | 原生本地化路径复制、三槽解析、追加、回退和安装；由variable64.c包含一次 |

## 共享机制的Interface与前提

```c
static int Var64_CopyTargetName(const unsigned char* field, char* out,
                               unsigned int outSize, Var64NameReadMode mode);
```

这是private Interface，不是通用安全字符串函数。
调用方必须先完成非NULL输出、现有容量门槛、复合目标校验和32字节字段可读检查。
字段布局保持：size在+16、capacity在+24、capacity<=15时使用内联数据，否则使用借用指针。
主名最大长度仍由 `VAR64_MAIN_NAME_LIMIT` 决定，失败不改输出，不分配、不释放、不改源字段。

| 调用方 | mode | 数据可读检查 |
|---|---|---|
| `Var64_ResolveGameVariableEx` | VAR64_NAME_BYTES_ONLY | size字节 |
| `Var64_ReadNameOnly` | VAR64_NAME_WITH_TERMINATOR | size+1字节 |

保留原逐字节复制，不以memcpy替换；不会额外加入capacity>=size等新限制。
因此共享的是两者相同的机制，不是把它们的接受/拒绝条件改成一样。
输出最低容量40、名称失败时原生outValue/outAddr是否保持不变、复合目标日志及原生调用顺序全部保留。

## 为什么操作数没有一起合并

操作数先清out[0]，允许容量>=8，无目标主名33字节限制，检查descriptor中的literal/复合字段，复制方式原来是memcpy。
这些规则不同于目标名称。继续保留独立实现，并把它作为三态对照中的对照路径，而不是通过新增一串策略开关强行塞进共享函数。

## 原生语言桥接片段

`variable64_language.inc`内容与本轮原始语言桥接块逐字相同：原函数调用、日志、借用字段、append RVA、原版回退与重复安装检查没有改写。
保留对父编译单元中 `Var64_Image`、数值/显示规则、字符串ABI类型和原生地址常量的依赖，不把这些暴露成新公共Interface。
该文件作为工程None项展示，不作为ClCompile项单独编译；不要在其他编译单元重复包含，否则会重复定义安装入口。
`Var64_ResolveAddressByName`的临时字段替换与恢复仍在原位置，未与本地化借用字段合并。
