# 原生数组只读后端与验证

> 历史阶段记录：全文的“本轮/当前/下一步”仅指当时实验，不是最新状态或可直接照抄的实施指令。现状见 [当前状态与复现](当前状态与复现.md)。旧方案、失败与旧偏移保留用于追溯，不覆盖现实现。

2026-10-12，HOI4 1.19.3 Windows x64。属于 Array64 接入前的只读存储验证，不开放任何 array64 写入。

## 已确认的存储结构

证据链：名称构造 RVA 0x5454A0 → 原版参数读取 RVA 0x544C90 → 只读查找 RVA 0xBC7E80。
静态反编译保存在 test/reports/20261012_variable64_transaction/array_readonly。
0x5454A0 为长度追加 `^num`，为元素追加 `^` 与转换后的十进制索引；0xBC7E80 查容器+16的表。
因此数组并非连续 vector，而是与标量共用容器的 `名称^num`、`名称^0`、`名称^1` 等变量键。
长度同样是 fixed-point raw，逻辑长度=raw/100000；标量 `名称` 是另一条键。
表桶指针在容器+24，mask在+36，节点48字节，字符串+8/size+24/cap+32，raw在+40。
Robin Hood 冲突向后连续溢出，不在 mask 边界回绕。新后端只读取，不调用可能插入的0xBC5C10。

## 接口与边界

独立源码：src/plugin/SDK_RVA/variable64/native_array_readonly.c。
`NativeArray_Read(container, name, index, output, count)`，通过调用者提供的 `na_read_memory` 安全复制内存。
读取成功返回1，输出元素原始 signed int64 与长度；失败不把元素输出清零。

| 返回 | 意义 | 输出 |
|---|---|---|
| 1 | 元素存在 | raw、count更新 |
| 0 | 长度键不存在 | raw、count保持 |
| 2 | 有效长度但索引越界，包括零长度 | count更新，raw保持 |
| -1 | 无效参数/名字/表、不可读内存、损坏字符串、查找超限 | raw、count保持 |
| -2 | 长度为负、带小数或超过4096 | raw、count保持 |
| -3 | 合法索引对应的元素键不存在 | raw、count保持 |

4096是候选后端的防护限额，不是查证出的引擎最大长度。
名字允许非空ASCII字母、数字、下划线，最多100字节；不接受global.、ROOT.或^索引。
容器必须先由原版解析器0x542500在有效CEventScope现场解析；禁止从名字猜scope或缓存旧指针。
后端是“已解析容器中的持久化存储读取”，不是完整脚本表达式解释器。
不自行模拟temp优先级、动态变量、复合名字、随机表达式、索引取整、作用域前缀。
调用者传入已求值的整数索引。只读长度不能证明所有元素齐全；完整形状检查需逐元素读取。
调用者必须在游戏线程/稳定现场执行，并负责避免并发写；可读检查不能提供跨线程原子快照。

## 实测与回归

MSVC单元夹具执行同一C源码，内存适配器仅允许预先登记的模拟原生布局区域。
覆盖4096元素、signed raw极值、负/小数/超限长度、缺失元素、负/上界索引、坏mask、
不可读内存、坏heap指针、SSO/长名字、同名标量隔离、Robin Hood末桶连续溢出与读前后逐字一致。
具体断言数、stdout/stderr/退出码见array_readonly/native_unit_final/result.json。
最终原生夹具4123/4123，通过且stderr为空、退出码0；MSVC /W4编译无警告。
夹具不等于游戏证据；游戏驱动将同一C源码直接编译成Frida CModule，在自定义trigger的同步现场调用。
适配器只复制内存，原版表达式与日志为独立对照；不是用JS另写一份后端代替执行C源码。
每阶段保存实际编译源码，要求与最终源码逐字一致；保存后退出，重新加载并重新解析全部容器。
验证本国、另一国、州、角色、global的同名数组、count、元素及同名scalar64隔离。
同时检查32字节保留数组名（实际^num键36字节）与缺失读取没有创建槽。
最终游戏往返42/42检查通过，write/reload各37次捕获均检查读取区域未变化，五类容器彼此不同。
本国[2.5,-0.125,7.75]、另一国[9.25]、州[-2,0]、角色[4.5]、global[6.125]均重启恢复；
同名scalar64均仍为12345678901.125，保留长名数组元素为1，marker=20261012，相关解析错误0。
读前后比较容器头与桶表含溢出区域；这仅证明这些被观察区域未变化，不宣称全进程无写入。

原版clear_array在本用例中删除长度键，清空后与未创建都返回“长度键缺失”。
后端支持“存在且raw长度=0”的空数组，但不能据此声称原版clear_array会保留该表示。
读取状态与原版数值0必须分开；未来创建、碰撞检查也必须检查残余元素键，不能仅检查^num。
