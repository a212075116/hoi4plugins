# 外部调试控制台第一版：使用与接口

2026-10-13：已实现独立Windows EXE、增量日志读取、本机双向管道和游戏线程调度，已编译部署并做真实游戏测试。
限定当前HOI4 1.19.3 x64单人环境。菜单/加载中无可用更新上下文时不从通信线程强行执行；等待最多5秒，超时请求明确取消且永不补执行。未超时请求会在上下文恢复时处理。
保留日志文件和原有记事本拦截。多人/Ironman限制走原版调度入口，不解除权限。

## 打开、关闭和重开

- 游戏以`-debug`或`-plugin-console`启动时自动打开；`-no-plugin-console`优先禁止自动打开。
- 已在地图中可输入原版游戏控制台命令`debugconsole`重开窗口；当前窗口存在时不重复创建。
- 也可直接运行游戏根目录的`hoi4_debug_console.exe`，自动寻找唯一的hoi4.exe；多个游戏需指定`--pid`。
- 关闭外部进程不结束游戏。游戏结束时外部进程退出。
- 不带debug也会初始化受限本机服务，便于手动打开；原版调度仍判断命令权限。

```powershell
Start-Process -FilePath 'D:\SteamLibrary\steamapps\common\Hearts of Iron IV\hoi4_debug_console.exe'
```

命令示例：`setcamheight 500`、`help setcamheight`、`event 事件ID`。
双引号可包含空格，`\"`与`\\`可转义；最多8个参数，整条输入最多2048个UTF-8字节。
首版不支持多条命令分号拼接，不把输入交给cmd.exe/PowerShell。原版`run`等命令仍按原版语义处理。

## 窗口本地操作

| 操作 | 作用 |
|---|---|
| `/help` | 本地帮助，不发给游戏 |
| `/filter all/game/error/plugin` | 实际输入格式为`/filter all`、`/filter game`等 |
| `/clear` | 清除窗口，不删除日志 |
| `/reconnect` | 重新连接当前游戏的管道 |
| `/quit` | 关闭终端，不关闭游戏 |
| 上/下方向键 | 最近128条会话内历史，不写磁盘 |
| 左/右/Home/End/Delete/Backspace | 编辑当前输入 |

输出刷新会重绘当前输入行；长输入采用水平窗口显示。
中文宽字符光标、超窄窗口、缩放和实际关闭按钮体验仍需用户确认，不以自测代替视觉验收。

## 三类日志与限流

增量读取用户文档目录`logs/game.log`、`logs/error.log`及游戏根`reports/mod_loader_tbb.log`。
每条输出添加读取时间和`[GAME]`、`[ERROR]`、`[PLUGIN]`来源；日志自带时间仍保留。
不同文件的刷新顺序不构成严格因果排序；尚未写出或刷新的内容不可读取。

- 支持暂不存在、部分行、跨读取UTF-8字符、截断和重新创建。
- 每个文件每200毫秒读取最多64KiB、输出最多256行；超额行会有跳过提示。
- 积压超过1MiB时跳过旧内容，只保留最新64KiB附近完整行，并显示提示。
- 超长单行达到64KiB时跳过；输出控制字符被替换，避免日志中的ANSI转义控制终端。
- 文件身份、大小和最近32字节哨兵用于识别截断后迅速增长；完全同内容重写等不可区分情况不保证识别。

## 命令的真实执行路径

```text
外部终端 → 本机命名管道 → 有界请求队列
→ 游戏主更新0xDD3A50返回后，核对窗口所属线程
→ 原版入口0x24B4D40（保留调用计数），进入0x24B4D60权限/查表调度
→ 请求ID/status/ok/执行线程/完整或有标记的截断message
```

IPC线程只收发和入队，不能从任意管道线程直接调用游戏函数。
有界请求队列容量32、最多4个连接、按入队序号FIFO，每个更新最多处理2条；执行时不缓存handler。插件命令注册完成之前拒绝执行，避免后台注册线程扩容命令表时并发读取。
游戏CString由游戏assign分配，输出复制后按原版小字符串/大块对齐规则释放；不是使用插件CRT随意free游戏内存。
这里“游戏线程”指命令调度入口，不意味着已有摄像机动画等插件后台任务都改成了主线程。

| status | 含义 |
|---|---|
| 0 | 已进入原版调度；成功与否看原版`ok`和`message` |
| 1 | 语法、就绪或输入校验拒绝，未调用原版调度 |
| 2 | 在执行前超时取消，之后不会补执行 |
| 3 | 原生异常，禁用此会话后续执行；不能保证异常前无部分效果 |

已经开始的原版命令不能强制中断。客户端等结果15秒后断开，会提示“执行结果未知”，绝不自动重试。
管道空闲30秒会断开；下一次发送先检测连接，可用`/reconnect`手动重连。
`help`全表超过8192字节时有截断标记；查具体命令用`help 命令名`，原版`helplog`可将详情写入日志。

## 安全与版本边界

命名管道为`\\.\pipe\hoi4-plugin-debug-v1-PID`，使用显式当前用户ACL、同Windows会话检查和`PIPE_REJECT_REMOTE_CLIENTS`。
首实例使用`FILE_FLAG_FIRST_PIPE_INSTANCE`，客户端核对服务PID与仍存活的游戏句柄，防止误连其他进程伪造的端点。
协议固定magic/version/request ID/length；同一连接ID需严格递增，超长/错版本等报文断开。
它不是同一用户下不同程序之间的强隔离边界；本机同用户的程序仍是受信任控制方。无TCP或远程执行入口。

首次启用检查PE时间戳`0x6AA123BB`和映像大小`0x37EC000`；不匹配时不安装本模块钩子。
这是版本兼容指纹，不是完整可执行文件签名校验。其他游戏版本需迁移RVA/ABI并重测。
预占端点和服务PID冒用的本机实测3/3通过；不完整/分片/重复ID报文4/4通过。
多人/Ironman拒绝分支做了谓词故障注入验证，不等于真实多人联机或真实Ironman存档验收。

## 实测中发现的旧摄像机竞态

快速执行`sch 500`后紧接`event zzc.1`，旧动画会把Effect设置的950.25写回500，三次均复现。
本轮修复`CameraSmoothStart`/`CameraSmoothThreadProc`：无变化目标不启动动画；新请求中断旧动画且同步写入新值，旧线程不再最终回写。
线程持有不可变参数快照，按原摄像机对象检查绑定；取消旧轨迹时不会承诺旧的中间动画仍完整走完。
已有普通共享路径9/9回归通过；快速同高目标3/3通过。视觉平滑和更广泛快速上下限组合仍不扩大为已验收。
