# 外部调试控制台：可行性与接口方案

状态：可实现的设计方案，未编写或部署交互控制台/命名管道服务。本轮不把“可以做”标成“已做完”。
目标：保留-debug记事本拦截，用一个独立窗口查看游戏/插件日志，并输入HOI4控制台命令。

## 当前项目已有基础

- process_block.c通过MinHook拦截CreateProcessA/W，命中notepad与.log时拒绝启动；不拦日志写入，也不提供交互控制台。
- Plugin_Log仍写游戏根reports/mod_loader_tbb.log；游戏日志仍由游戏写入用户文档目录logs/。
- exec_console_command.js已经从真实命令表按名解析handler，构造CmdArgs/CmdResult并调用，读取ok/message；原版event与插件setcamheight等已有实测。
- 因此不是要重新实现游戏命令语义，而是补日志终端、通信、生命周期和安全调度。

## 推荐结构

```text
游戏日志文件 + reports/mod_loader_tbb.log
              ↓ 增量读取
独立Windows控制台程序：显示来源/时间/级别，保留当前输入行
              ↓ 命令请求（本机双向IPC）
插件通信接收 → 有界请求队列 → 已验证的游戏执行上下文
              ↓ 解析真实命令表/调用handler
命令结果ok/message、请求ID → 外部窗口
```

独立控制台进程比在游戏内AllocConsole更容易隔离窗口关闭、输入阻塞和终端绘制。
可用CreateProcess的CREATE_NEW_CONSOLE创建新控制台；实际启动选项/路径需实现时验证，不在CreateProcess hook回调或DllMain里直接做重活。
只启动一个实例、识别游戏PID/会话；默认在-debug启用，可提供手动开关。关闭外部窗口不退出游戏，不取消原有日志文件。

## 输出通路

首版增量读取game.log、error.log和mod_loader_tbb.log，显示[GAME]/[ERROR]/[PLUGIN]来源；其他日志按配置增加。
处理文件暂不存在、部分行、编码、文件截断/游戏重启与轮换；不要每次全量读大文件，不宣称读取尚未写出/刷新到文件的内容。
独立文件时间戳/刷新顺序可能不同，合并显示不是严格的跨线程因果排序。
大量日志应有上限、限速/丢弃提示和来源过滤；日志刷新不能覆盖用户正在输入的命令。
若以后需要更低延迟，可追加非阻塞插件日志通道；不能把游戏逻辑线程阻塞在窗口/管道写入上。

## 输入通路与重要限制

建议本机命名管道，双向传递带长度/请求ID的命令和结果；限制单条长度、队列容量与执行超时。
只按原版控制台命令/参数解析，不把输入交给cmd.exe/PowerShell作为操作系统命令执行；支持引号参数，不能简单按空格拆掉语义。
已有ConsoleCmd表与Frida探针证明命令执行可行，但生产版不宜长期依赖Frida attach/spawn。
IPC线程只收发/入队；真正执行要在经过验证的游戏上下文调度，不能从任意管道线程直接调用游戏函数。
现有GameDate UI hook不是已完成的通用主线程调度器；暂停/菜单/读档时能否处理请求必须单独验证。
每次执行重新查表，不跨重新注册/读档长期缓存handler/对象地址；正确构造与释放游戏字符串，区分命令返回失败、未执行、超时与游戏退出。
限制本机和当前登录用户，显式ACL/会话校验、防端点冒用；默认命名管道权限不是“仅当前用户”保证。网络/远程控制不在首版范围。

## 原有拦截如何保留

保持记事本拒绝逻辑；外部程序不叫notepad，独立初始化后启动，不把记事本进程成功信息伪造给游戏。
目前拦截条件实际是notepad+.log，并非逐次核对-debug标志；新控制台的启用策略要另设，不能把当前钩子当debug模式检测器。

## 实现后的自动验收

同一游戏会话只出现一个窗口；三类日志持续显示；输入setcamheight 500/event/help等已存在命令得到真实ok/message。
游戏菜单/地图/暂停/读档/退出、窗口关闭重连、大日志刷屏、错误命令、含空格参数、权限与端点冲突均需测试。
这份方案不声称所有命令在多人、Ironman、无调试环境或任意线程都可用，也不是解除游戏权限/限制的工具。
