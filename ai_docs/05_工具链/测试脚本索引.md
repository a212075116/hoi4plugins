## 命名约定

| 形式 | 含义 |
|---|---|
| `probes_js/_xxx.js` | 探针。用 `rpc.exports = { 方法名: function(){...} }` 暴露能力 |
| `tools/_xxx_run.py` | 运行脚本。加载对应探针、调用其方法、打印结果 |
| `tools/xxx.py`（无下划线） | 工具类，如 `idalib_cli.py`、`gen_def.py`、`strip_comments.py` |

下划线前缀表示「一次性探针」，**不要当成稳定接口**；稳定接口在 `src/plugin/`。

## 写一个测试的标准流程

```python
import sys, time, importlib.util
sys.path.insert(0, r'<root>/hoi4plugins/test/tools')
spec = importlib.util.spec_from_file_location('fh', r'<root>/hoi4plugins/test/probes_frida/frida_host.py')
fh = importlib.util.module_from_spec(spec); spec.loader.exec_module(fh)

pid, session, sc, fresh = fh.connect(r'<root>/hoi4plugins/test/probes_js/_xxx.js',
                                     force_spawn=False)   # ← 见下方陷阱
e = sc.exports_sync        # e.方法名(...) 即可调用探针
print(e.ready())
fh.detach(session)
```

## 必须知道的陷阱：不要用 spawn

**`frida.spawn` 出来的游戏进程，会随宿主 Python 进程结束而被一起终止。**

所以：

| 做法 | 结果 |
|---|---|
| `force_spawn=True` | 脚本一退出，游戏就没了。**会被误判成「游戏崩溃」** |
| `force_spawn=False` + 外部 `Start-Process` 启动游戏 | 脚本退出后游戏仍存活 ✓ |

标准做法是**用 PowerShell 的 `Start-Process` 独立启动游戏**，再 `connect(force_spawn=False)`。

这个坑代价很大：曾经因为它把一次正常的日期写入误判成崩溃，查了很久。
（`%LOCALAPPDATA%\CrashDumps` 无 dump、事件日志无记录 —— 这些都是「不是崩溃」的信号。）

## 游戏没进图时的现象

`CGameState`（`*(hoi4.exe+0x332F260)`）非 NULL 只代表「游戏状态已建立」，
**主菜单也可能非 NULL**。真正的判据是 `game.log` 里的 `[[ Launching SINGLEPLAYER-game ]]`。

`fh.wait_in_game()` 读的正是这个标记；`fh.wait_game_ready()` 是轮询 `CGameState`
并额外等几秒。**两者在主菜单都可能给出「就绪」的误判**，要结合作业目的选择。

另有两点：

- 游戏进图后**默认暂停**，日期不推进。要 `auto_unpause <1..5>` 才会走
- **正在初始化的那一小段时间里写入会被游戏重置**（实测：进图后 10 秒内写日期会被改回去，等稳定后再写就正常）

## frida_host.py 的公开函数

| 函数 | 说明 |
|---|---|
| `set_start_tag(tag)` | 设置启动用的 `-start_tag=`；**不设置就没有 tag，游戏会停在主菜单** |
| `find_pid()` | 找 hoi4.exe，返回 pid 或 None |
| `in_game()` | 读 `game.log` 判是否已进战略地图 |
| `wait_in_game(timeout, tag)` | 轮询上面的判据，返回 bool |
| `connect(js_path, force_spawn, wait, tag)` | attach 或 spawn + 加载探针，返回 `(pid, session, sc, fresh)` |
| `wait_stable(sc, fn, key, ...)` | 轮询某方法直到结果连续不变 |
| `wait_game_ready(session, ...)` | 轮询 `CGameState` 并额外等待 |
| `detach(session)` | 断开（**建议每次脚本结束都调**） |

## 触发 effect 用的测试事件

effect 不能直接调，要靠事件触发。测试事件建在 **mod** 里（不在本仓库）：

| 文件 | 内容 |
|---|---|
| `mod bakaifa/events/zz_datetest.txt` | 11 个事件：3 个 set_game_date + 8 个加减 |
| `mod bakaifa/localisation/zz_datetest_l_english.yml` | 对应本地化 |

正确写法（**踩过坑**）：

    add_namespace = zzdatetest          // 不是 namespace =
    country_event = {                   // 必须有这层包裹
        id = zzdatetest.1
        hidden = yes
        is_triggered_only = yes
        immediate = { set_game_date = 510.6.7.0 }
        option = { name = zzdatetest.1.a }
    }

只写 `zzdatetest.1 = { ... }` 会报 `Unexpected token`（看 `logs/error.log`）。
触发用控制台 `event zzdatetest.1`。
