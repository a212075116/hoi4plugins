# 启动游戏与就绪判断

> 目的：**不准盲等**。每一次等待都要有可轮询的信号。
> 核对2026-10-12；耗时为旧机器观察，不是通用保证。

## 为什么

早前用 `Start-Sleep -Seconds 90` 等游戏启动，浪费大量时间，
而且时间到不代表就绪、时间没到也可能已就绪。

## 四种启动/部署方式（按推荐顺序）

### 1. `test/tools/hoi4_launch.py`（推荐）

```python
import sys
ROOT = r'D:/SteamLibrary/steamapps/common/Hearts of Iron IV'
sys.path.insert(0, ROOT + '/hoi4plugins/test/tools')
import hoi4_launch as HL

HL.deploy()                                   # 杀游戏 + 覆盖 tbb.dll 与 hoi4_mod_plugin.dll
dt, _ = HL.launch(args=['-gdpr-compliant', '-start_tag=ABY', '-nolauncher', '-force_text_save'],
                  wait_marker='[plugin] Camera_RegisterCommands', timeout=200)
```

| 函数 | 作用 |
|---|---|
| `deploy()` | 先杀 hoi4，再复制 `build/Release/` 的两个 DLL；文件被占用时会重试 |
| `launch(args, wait_marker, timeout)` | 杀旧进程 → 清插件日志 → `Popen` 启动 → 按标记轮询 |
| `build_and_launch(marker, timeout, args, skip_build)` | 构建+部署+启动 三合一 |
| `wait_for(marker, timeout, poll)` | 轮询插件日志；**进程死掉立刻抛错** |
| `status()` | 回显最近的 `[eff]` / `[plugin]` / `[scan]` 行 |

### 2. 手动 `Start-Process`

```
Get-Process hoi4 -ErrorAction SilentlyContinue | Stop-Process -Force
Start-Sleep -Seconds 5            # 等文件解锁, 否则 LNK1201 / 复制失败
Copy-Item '<build>/hoi4_mod_plugin.dll' '<游戏根>' -Force
Copy-Item '<build>/tbb.dll' '<游戏根>' -Force
Start-Process -FilePath '<游戏根>/hoi4.exe' `
  -ArgumentList '-gdpr-compliant -start_tag=ABY -nolauncher -force_text_save' `
  -WorkingDirectory '<游戏根>'
```

然后**轮询**等进图，不要盲等：

```
for ($i = 0; $i -lt 70; $i++) {
  Start-Sleep -Seconds 2
  if ((Get-Content '<日志>/game.log' -Raw) -match 'Launching SINGLEPLAYER-game') { break }
}
Start-Sleep -Seconds 30           # 进图后还要等初始化稳定
```

### 3. 禁止：`frida.spawn`

spawn 的游戏进程随宿主 Python 结束一起死，**会被误判成崩溃**。
详见 `test/docs/README.md` 的「三条硬规则」。

## 四个不同的就绪点

| 就绪点 | 信号 | 实测耗时 |
|---|---|---|
| **lexer 就绪** | `byte_1435E1AB0` && `byte_1435E1AB1` 均为 1 | **约 2.2 秒** |
| **effect 可注册/可测** | 插件日志出现 `[eff] camera height effect ready` | **约 3.5 秒** |
| **到达摄像机命令注册阶段** | 插件日志出现 `[plugin] Camera_RegisterCommands` | **约 14.4 秒** |
| **进地图（可测游戏内数据）** | `game.log` 出现 `Launching SINGLEPLAYER-game`，且进图后再等 ~30 秒 | 视机器而定 |

**注意**：`CCurrentGameState`（`0x332F260`，即 `RVA_GS_GLOBAL`）非空 **不代表进入地图**，
主菜单时它也可能非空。判断「进地图」要看 idler 的类型：
主菜单是 `CFrontEndIdler`（`+0x750` 不是有效摄像机指针），
进地图后是 `CInGameIdler`（`+0x750` 是摄像机）。

## 插件日志位置

```
<游戏根>/reports/mod_loader_tbb.log
```

**每次验证改动是否生效，必须同时看 DLL 时间戳和日志里是否出现新格式**，
否则可能读到旧 DLL 的结果（这个坑踩过）。

## Frida 侧的就绪探测

`lib/exec_console_command.js` 提供：

| 接口 | 返回 |
|---|---|
| `ready()` | `{ok, idler, cam, h}`；`ok=false` 时带 `why` |
| `camHeight()` | 高度 float，无效时返回 -1.0 |
| `cam()` | 可读的三字段字符串 |
| `exec(name, args)` | 进程内执行控制台命令 |

这样「等摄像机可用」也能轮询，不用盲等：

```python
while time.time() - t0 < 120:
    if e.ready()['ok']: break
    time.sleep(0.4)
```

## 效率对比

| | 之前 | 现在 |
|---|---|---|
| 等游戏可测 effect | 90 秒（盲等） | **3.5 秒**（轮询 `[eff]` 标记） |
| 等到达摄像机命令注册阶段 | 90 秒（且可能不够） | **约 14.4 秒**（轮询 `[plugin] Camera_RegisterCommands`） |

该标记不保证全部注册成功：必须检查scalar64、Array64 effects=10/10及trigger=1/1等对应结果，再确认地图/读档就绪。
HL.launch不部署，HL.deploy不构建；阶段顺序与SHA-256必须核对。现有驱动的标记后32秒是保守稳定期，不是注册成功证据。
connect(force_spawn=False)在无PID时仍spawn，必须先检查PID。真正进程终止以Windows句柄信号/退出码确认，tasklist即时结果与RPC销毁通知可能滞后。
