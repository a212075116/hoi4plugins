# 启动游戏与就绪判断

> 目的：**不准盲等**。每一次等待都要有可轮询的信号。

## 为什么

早前用 `Start-Sleep -Seconds 90` 等游戏启动，浪费大量时间，
而且时间到不代表就绪、时间没到也可能已就绪。

## 三个不同的就绪点

| 就绪点 | 信号 | 实测耗时 |
|---|---|---|
| **lexer 就绪** | `byte_1435E1AB0` && `byte_1435E1AB1` 均为 1 | **约 2.2 秒**（插件线程第 208~212 次 10ms 轮询） |
| **effect 可注册/可测** | 插件日志出现 `[eff] camera height effect ready` | **约 3.5 秒** |
| **插件完全就绪** | 插件日志出现 `[plugin] Camera_RegisterCommands` | **约 14.4 秒** |
| **摄像机可测（进地图）** | `idler = *(0x332F698)` 非空，且 `*(idler+0x750)` 是有效指针且高度合理 | 再约 8 秒 |

**注意**：`CCurrentGameState`（`0x332F260`，即 `RVA_GS_GLOBAL`）非空 **不代表进入地图**，
主菜单时它也可能非空。判断「进地图」要看 idler 的类型：
主菜单是 `CFrontEndIdler`（`+0x750` 不是有效摄像机指针），
进地图后是 `CInGameIdler`（`+0x750` 是摄像机）。

## 工具

    test/tools/hoi4_launch.py

| 函数 | 作用 |
|---|---|
| `launch(args, wait_marker, timeout)` | 杀旧进程 → 清日志 → 启动 → 按标记轮询等待 |
| `wait_for(marker, timeout, poll)` | 以 0.15 秒间隔轮询插件日志；进程死掉会立刻抛错 |
| `status()` | 回显最近的 `[eff]` / `[plugin]` / `[scan]` 行 |

用法：

    import hoi4_launch as HL
    dt, _ = HL.launch(wait_marker='[plugin] Camera_RegisterCommands', timeout=150)
    print('就绪耗时 %.2f 秒' % dt)

## Frida 侧的就绪探测

`test/probes_js/_exec_cmd.js` 提供：

| 接口 | 返回 |
|---|---|
| `ready()` | `{ok, idler, cam, h}`；`ok=false` 时带 `why` |
| `camHeight()` | 高度 float，无效时返回 -1.0 |
| `cam()` | 可读的三字段字符串 |
| `exec(name, args)` | 进程内执行控制台命令 |

这样「等摄像机可用」也能轮询，不用盲等：

    while time.time() - t0 < 120:
        if e.ready()['ok']: break
        time.sleep(0.4)

## 效率对比

| | 之前 | 现在 |
|---|---|---|
| 等游戏可测 effect | 90 秒（盲等） | **3.5 秒**（轮询） |
| 等进地图 | 90 秒（且可能不够） | **约 22 秒**（轮询） |
