# 成就兼容：资格链路与阶段进展

2026-10-13，HOI4 1.19.3 x64，EXE SHA256 `7dc947be34970da1e1c787bcddbe7f62b610ff258aebf8f06aa8b348f3a031d5`。

**当前完成策略基础、只读探针和原版定义来源第一版。真正的资格放行Hook、候选恢复和Steam真实解锁尚未实现/验收，不得宣称成就已可用。原版来源的读取检查通过不代表间歇退出已修复。**

## 用户契约

- 放宽非铁人、mod/资格校验和等环境资格，而不把所有`possible`或`happened`判定为true。
- 保留国家、领土、科技、事件等真实条件及原生提交链路；不批量解锁，不重置账号成就。
- 本阶段不调用Steam成就修改接口，不编辑原版或mod成就文件。
- 始终使用游戏根目录的原版`common/achievements.txt`，忽略mod对该公开文件的空/非空覆盖。
- 用户允许真实游戏行为满足条件并实际解锁账号成就；不允许据此把直接赠送或伪造条件当作验收。

## 已确认的路径

| RVA | 观察到的用途 | 证据 |
|---|---|---|
| `0x61CD20` | 成就manager惰性获取，大小0xA8，全局槽0x3330460 | 当前EXE指令与IDA反编译 |
| `0x6201F0` | 总资格查询；读取manager+0xA1/A2/A3及debug全局标志 | Getter反编译 |
| `0x6207E0` | 加载`common/achievements.txt`，后续加载mod自定义定义 | 字符串引用与反编译 |
| `0x6202C0` | 根据`possible`重建候选列表 | 原生条件节点虚调用，未改写 |
| `0x620570` | 从存档候选ID恢复列表，区别于重新评价possible | 反编译 |
| `0x621040` | 运行时检查`happened`并进入原生完成流程 | 节点+24与完成调用 |
| `0x61CE50` | 完成处理，普通成就进入原生平台提交适配器 | A3调试分支会跳过适配器 |
| `0x1484FC0` | mod成就云存储读取和完整性验证 | `achievements_mod_storage.cpp`与checksum错误分支 |

不要绕过0x1484FC0的存储完整性检查。它不是“有mod仍允许原版成就”的资格门。
不要用manager+0xA3的调试模式作兼容捷径：它能显示/模拟结果，但原生提交适配器会被跳过。
资格条件被多处内联，单Hook总资格Getter不足以处理新局、旧存档和每次运行检查。

铁人条件的共同Eval包装器是0x54D0B0，不能对这个共享包装器统一返回true。
`CIsIronmanTrigger`的实际实现位于0x3DB5C0，尾部比较game_state+0xC0低位和条件对象+0x58预期值；未来只能在受控的原版成就资格评价中处理它，不能影响`happened`或所有游戏Trigger。

## 历史空覆盖与当前现场

第一阶段测试曾启用`bakaifa`和音乐mod；`bakaifa/common/achievements.txt`为0字节，导致当时definitions=0。
这不是当前CHI测试局的配置；后续现场已读到293个定义、候选为0，资格兼容仍未开启。
不能只把资格Getter改为true。公开同名文件一律忽略mod覆盖；独立mod自定义成就目录保留原生处理，不与公开文件覆盖混淆。
mod缺失原版国家/科技/事件标志时，对应成就可能仍无法达成；不应伪造这些条件。

## 已实现的基础

`achievement_policy.h`是未接入原版Hook的纯决策模型：兼容模式只忽略铁人和资格checksum两个输入，仍要求会话、单人、平台及其他possible成立；提交还要求happened且未解锁。
512组合通过；参考基线模型509/512、修改512/512、回滚509/512，退出码1/0/1。这不是原版成就全量验收。
`achievementstatus`（别名`achstatus`）仅读取版本受限的manager/铁人/调试字段，明确输出兼容Hook未启用。
实机基线Unknown command，修改后读取成功，DLL回滚后恢复Unknown command；100次读取后manager全部168字节哈希不变。

## 原版定义来源第一版

`AchievementSource_Install`在插件线程早期安装三个受版本限制的Hook。
仅在0x6207E0原版加载器的线程局部上下文内，将精确同名的存在性查询和CTextLexer文件参数重定向。
直接用Win32读取游戏根目录原版文件，生成只含该文件的内存ZIP，挂载到私有VFS命名空间。
不把原版定义挂到公开common目录，不写入原版/mod文件，不更改全局debug或铁人位。
Hook原函数指针在批量启用前发布；上下文用`__finally`恢复；内存存活至卸载回调释放。
原版文件空/超过16MiB、读取/挂载失败或私有路径冲突时报告失败，不回退mod公开定义。
文件内容是本次进程加载时的原版快照；更换游戏文件后须重新启动，不承诺运行中热更新。
私有来源路径：[PhysicsFS mountMemory官方接口](https://wiki.icculus.org/PhysicsFS3/PHYSFS_mountMemory)。
实机已见`installed=1 mounted=1 loads=1 redirects=1 failures=0 definitions=293`。
非空公共覆盖夹具的私有来源隔离7项检查通过，manager168字节不变；没有重跑原生解析器或调用Steam。
生产头文件边界/精确匹配16项通过，生成ZIP由Python独立校验CRC与内容。
本阶段遇到一次用户报告的自行退出、未生成新游戏崩溃目录；退出原因尚未知。
随后不附加Frida的180秒观察中进程仍存活，用户正常入图；不能据此宣称间歇问题消失。
详见[原版来源测试](../../test/docs/achievement_original_source.md)。
