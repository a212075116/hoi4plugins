# 复现虚表索引表（从零开始）

> 目标：让你自己在本地从 `hoi4.exe` 生成 `.i64`，再跑出与仓库里
> `sources/1.19.3/vt_index_1.19.3.json` 一致的索引表。

## 为什么 `.i64` 不在仓库里

IDAPython 的数据库（`.i64` + `.id0/.id1/.nam/.til`）合计约 **1.7 GB**，
而且是**中间产物** —— 它完全可以从 `hoi4.exe` 重新生成。
把它放进版本控制没有意义（体积大、且随工具版本变化）。

**仓库里保存的是可复现的脚本，不是产物。**

## 前置条件

| 项 | 要求 | 说明 |
|---|---|---|
| 操作系统 | Windows x64 | idalib 是 Windows 原生库 |
| 游戏本体 | HOI4 **1.19.3** | 本项目全部 RVA 基于该版本；版本变化后须重核，不能默认沿用 |
| IDA | **9.0 或更高，且有 idalib + Hex-Rays** | 9.0 是作者验证过的版本 |
| Python | 3.9+（作者用 3.13.2） | 需要能 `import idapro` |
| 磁盘 | **至少 5 GB 空闲** | `.i64` 系列约 1.7 GB |

## 步骤 1：确认游戏本体

`hoi4.exe` 在游戏根目录，约 53 MB。确认版本：

    # Steam 里右键 HOI4 -> 属性 -> 已安装文件；或看启动器右下角版本号

**必须是 1.19.3。** 换版本必须重新核对RVA/ABI，不保证部分或全部偏移保持。

## 步骤 2：用 IDA 生成 .i64

### 方式 A：图形界面（最稳，推荐首次）

1. 打开 IDA（`ida64.exe`）
2. `File -> Open`，选游戏根目录的 `hoi4.exe`
3. 弹出格式选择时保持默认（Portable executable），点 OK
4. **等自动分析跑完**（状态栏不再滚动）。约 144000 个函数，**耗时数小时**
5. `File -> Save database`（或 Ctrl+W），存为 `hoi4.exe.i64`

### 方式 B：命令行批处理

    idat64.exe -A -c -o"hoi4.exe.i64" "<游戏根目录>\hoi4.exe"

| 参数 | 含义 |
|---|---|
| `-A` | 自动模式，不弹任何对话框 |
| `-c` | 生成新数据库（不加载已有） |
| `-o` | 输出数据库路径 |

> **注意**：`-A` 会在分析完成后自动退出。若担心中途失败，先手工跑一次方式 A。
> 两种方式产出的 `.i64` 内容等价，都可用于后续步骤。

## 步骤 3：放到版本目录

    hoi4plugins/sources/1.19.3/
        hoi4.exe.i64
        hoi4.exe.id0      <- IDA 自动生成，跟着 .i64 走
        hoi4.exe.id1
        hoi4.exe.nam
        hoi4.exe.til

**目录名就是游戏版本号**，将来 1.20 放 `sources/1.20/`，两版可并存。

这些文件已被 `.gitignore` 排除，不会误提交。

## 步骤 4：装 Python 侧依赖并确认路径

    pip install idapro

`idalib_server.py` 里两处可被环境变量覆盖，默认值是作者的机器路径：

| 环境变量 | 作用 | 默认 |
|---|---|---|
| `IDADIR_OVERRIDE` | IDA 安装目录 | `D:\IDA Professional 9.0` |
| `IDALIB_I64` | `.i64` 路径 | `.../hoi4plugins/sources/1.19.3/hoi4.exe.i64` |
| `IDALIB_PORT` | 监听端口 | `19531` |

路径不同就设环境变量，例如：

    set IDADIR_OVERRIDE=C:\Program Files\IDA 9.0
    set IDALIB_I64=D:\work\hoi4.exe.i64

## 步骤 5：启动 idalib 服务

    python hoi4plugins/test/lib/idalib_server.py

预期输出：

    [idalib] open_database ...
    [idalib] open rc=0  用时 7.1s
    [idalib] imagebase=0x140000000  hexrays=True
    [idalib] 监听 127.0.0.1:19531  就绪

**开库约 6-8 秒**（对比 `idat.exe` 每次冷启动要 3-5 分钟）。

服务常驻，所有后续查询都走这个 TCP 端口。

自检：

    python hoi4plugins/test/lib/idalib_cli.py ping

应返回：

    {"ok": true, "imagebase": "0x140000000", "min_ea": "0x140000000",
     "max_ea": "0x144000000", "funcs": 144103, "input": "..."}

## 步骤 6：生成索引表

    python hoi4plugins/test/probes_ida/vtable/build_vt_index.py <输出.json>

**耗时约 6.5 秒。**

    [0/3] 探测服务与镜像范围 ...
          imagebase = 0x140000000   max_ea = 0x144000000   funcs = 144103
    [1/3] 取 ??_7 符号 ...
          共 12333 个
    [2/3] 解析 RTTI 与槽位 ...
    [3/3] 写出 ...
    完成: 12333 个虚表, RTTI 成功 12333, 总用时 6.5s

可选：排版成人类可读形式

    python hoi4plugins/test/probes_ida/vtable/reformat_vt_index.py <输入.json> <输出.json>

## 步骤 7：校验复现结果

**直接用校验脚本**（推荐）：

    python hoi4plugins/test/probes_ida/vtable/verify_vt_index.py <你的输出.json> <参考索引.json>

参考索引就是仓库里的 `sources/1.19.3/vt_index_1.19.3.json`。通过时输出：

    硬指标校验
      虚表总数         12333   期望    12333   OK
      RTTI 成功        12333   期望    12333   OK
      槽总数          496650   期望   496650   OK
    关键类校验
      CInGameIdler         rva=0x02968ff0  n=64  OK
      CFrontEndIdler       rva=0x02949d50  n=64  OK
      CCurrentGameState    rva=0x02721158  n=45  OK
      CCountry             rva=0x027e7360  n=64  OK
      CArmy                rva=0x0295a2b0  n=64  OK
    端到端校验
      CInGameIdler 槽[38] (+0x130) = 0x00dc53b0   OK
    与参考索引表逐条比对
      rva 集合相同        : True
      slots 不同的条数    : 0
      cls   不同的条数    : 0
    结论: 校验通过

不带参考文件也可以，只做硬指标 + 关键类 + 端到端校验。

### 7.1 硬指标（由游戏本身决定，必须一致）

| 项 | 期望值 |
|---|---|
| 虚表总数 | **12333** |
| RTTI 解析成功 | **12333** |
| 槽总数 | **496650** |

### 7.2 关键类（由游戏本身决定，必须一致）

| 类 | 虚表 RVA | 槽数 |
|---|---|---|
| `CInGameIdler` | `0x02968FF0` | 64 |
| `CFrontEndIdler` | `0x02949D50` | 64 |
| `CCurrentGameState` | `0x02721158` | 45 |
| `CCountry` | `0x027E7360` | 64 |
| `CArmy` | `0x0295A2B0` | 64 |

### 7.3 端到端（本项目运行时实证过的一条）

    CInGameIdler 的槽[38]（+0x130）= 0x00DC53B0      <- cam getter

这一条特别有价值：它是**静态索引表**与**运行时行为**对上的证据。

### 哪些东西可能因人而异

| 字段 | 是否确定 | 说明 |
|---|---|---|
| `rva` / `slots` / `n` | **确定** | 由 PE 文件本身决定 |
| `cls` | **确定** | 由内存中的 RTTI 决定 |
| `nbase` | **确定** | 同上 |
| `sym` | **可能不同** | 来自 IDA 符号表；**demangler 或 FLIRT 签名差异会改变符号名** |

所以校验**以 `rva` / `slots` / `cls` 为准**，不要拿 `sym` 比对。
校验脚本也刻意跳过 `sym`。
## 故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| `找不到数据库` | `IDALIB_I64` 指错或 `.i64` 还没生成 | 见步骤 2、4 |
| `import idapro` 失败 | 没装 `idapro` 包，或 `IDADIR` 不对 | `pip install idapro`；设 `IDADIR_OVERRIDE` |
| `open rc!=0` | `.i64` 损坏或版本不匹配 | 重新生成 |
| 虚表数远小于 12333 | 游戏版本不对 | 确认 1.19.3 |
| `WinError 10048` | 客户端每请求新建连接，端口耗尽 | 用仓库里的 `idalib_cli.py`（已改持久连接） |
| `Function can be called from the main thread only` | 多线程调 IDA API | 服务端必须串行处理（仓库版本已如此） |
| `cls` 全是乱码 | RTTI 指针按 8 字节读了 | 必须按 **4 字节 RVA** 读，见《虚表与RTTI》 |
