## 公共日志 Interface

```c
void Log_AppendV(const char* path, const char* format, va_list arguments);
```

调用者提供有效路径、格式和已初始化的参数列表，并负责 `va_start/va_end`。
当前实现同步追加一条记录，按原有策略忽略打开/写入失败，不创建目录、不重试、不引入后台线程。
消息缓冲2048字节、输出行2304字节；消息格式化溢出时整条丢弃，不打开文件。
路径仍由 `carrier.h` 的 `LOADER_LOG_DIR` 决定；本轮集中配置，但没有把现有固定路径改成自动发现。
载体早期日志的时序与依赖不同，没有强行迁入此模块。

## 字符串所有权不能顺手改

`CmdString` 的大小32、SSO容量15、原生assign RVA均保持。
本轮只合并重复实现，不更改现有长字符串转短字符串时的所有权行为，也没有新增 `free`。
将来如要调整释放或重用，必须单独验证游戏原生分配器与调用方生命周期，不能用CRT释放游戏内存。

## 重构顺序

1. 记录源文件哈希、构建产物和现有行为。
2. 从确实重复的机制开始，不以相似函数名或行数决定合并。
3. 保留外部 Interface，用较小的内部实现替换重复代码。
4. 同输入运行BASELINE、MODIFIED、ROLLBACK，比较stdout、stderr和退出码。
5. 同步工程编译清单、夹具链接依赖、技术文档和测试索引。
6. 区分源码完成、构建完成、部署完成、实机验收，不互相代替。
