2026-10-13。目标是让维护者理解职责、复用正确实现，并在重构后保留可复现的行为证据。

## 已完成的职责收拢

| 原重复或混杂位置 | 当前实现 | 不变的行为 |
|---|---|---|
| `Plugin_Log` 与 `ConsoleCmd_DefaultLog` 各自实现格式化、时间戳、文件追加 | 共用 `SDK_RVA/common/log.c` 的 `Log_AppendV`，原入口保留薄适配 | 原文件名、时间戳、CRLF、共享模式、消息溢出丢弃 |
| `ConsoleCmd_SetMessage` 重复原生字符串赋值分支 | 调用已有 `ConsoleCmd_WriteString` | SSO15字节、长字符串走原生赋值、无模块时截断、保留 `out->ok` |
| 外部控制台 `main.cpp` 同时处理编辑与远程表结构 | 只读查询独立到 `command_catalog.cpp/.h` | 原PID、PE指纹、读取权限、表一致性检查与有界重试 |
| 不再使用的 `ParseHelp` 文本解析器 | 删除，候选筛选/排序/去重共用 `Completion::Matching` | 真实注册名称/别名来源，不退回依赖地图执行上下文的help调用 |

`main.cpp` 保留输入、显示、异步队列和过期结果拒绝。
`completion.h` 只放纯计算：有效名称匹配、共同前缀、首词范围、快照比较、行数和配色。
`CommandCatalog::Query(pid, prefix, error)` 处理只读候选获取；调用者传入PID，不读取编辑状态，也不执行指令。
候选每行最多5个、全列表奇偶交替配色的实现没有改动。

## 公共日志 Interface

```c
void Log_AppendV(const char* path, const char* format, va_list arguments);
```

调用者提供有效路径、格式和已初始化的参数列表，并负责 `va_start/va_end`。
当前实现同步追加一条记录，按原有策略忽略打开/写入失败，不创建目录、不重试、不引入后台线程。
消息缓冲2048字节、输出行2304字节；消息格式化溢出时整条丢弃，不打开文件。
路径仍由 `carrier.h` 的 `LOADER_LOG_DIR` 决定；本轮集中配置，但没有把现有固定路径改成自动发现。
载体早期日志的时序与依赖不同，没有强行迁入此模块。

## 字符串所有权不能顺手改

`CmdString` 的大小32、SSO容量15、原生assign RVA均保持。
本轮只合并重复实现，不更改现有长字符串转短字符串时的所有权行为，也没有新增 `free`。
将来如要调整释放或重用，必须单独验证游戏原生分配器与调用方生命周期，不能用CRT释放游戏内存。

## 重构顺序

1. 记录源文件哈希、构建产物和现有行为。
2. 从确实重复的机制开始，不以相似函数名或行数决定合并。
3. 保留外部 Interface，用较小的内部实现替换重复代码。
4. 同输入运行BASELINE、MODIFIED、ROLLBACK，比较stdout、stderr和退出码。
5. 同步工程编译清单、夹具链接依赖、技术文档和测试索引。
6. 区分源码完成、构建完成、部署完成、实机验收，不互相代替。
