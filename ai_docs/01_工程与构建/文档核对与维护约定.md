## 自动审计与其能力边界

```powershell
python test/tools/audit_project_docs.py --output docs_audit.json
```

检查UTF-8、300行限制、围栏闭合、本地Markdown链接、现行测试CLI存在性和选定现状合约。
原始内容备份、清单、基线/修改/回滚结果位于test/reports/20261012_variable64_transaction/docs_audit/。
不会自动认证全部静态函数/RVA、外部链接、外部mod配置或所有历史实验事实；本轮没有重新跑游戏/IDA/联网确认这些内容。
历史依据保留但必须显式标明阶段，动态绝对地址、耗时、PID、机器依赖都不是跨运行常量。

## 后续维护规则

1. 当前合约、历史过程与未验证猜测分开；改变代码时同步更新当前入口，不能只在旧文章尾部追加“下一步”。
2. 每篇严格≤300行，按主题/章节拆分；原文件名留索引避免旧引用失效，不截断证据或代码围栏。
3. 新测试写明启动/部署/构建是否独立、是否重启/保存、fixture与检查点要求、输出目录和副作用。
4. 保存日志的--verify-only若仍读取当前进程/DLL，应明示，不称为完全离线；旧检查点不可直接套最新a64soak。
5. 单人字符串/原生夹具通过，不自动提升为GUI、掉电、多人或多小时资源通过。外部不在仓库的记录应标外部，不写成可打开的本地文件。
6. reconcile_project_docs.py是本轮一次性迁移记录，不应重复执行已完成拆分；正常维护使用审计器。

Evidence：当前源码、各轮已有comparison及docs_audit基线内容。
Finding：过时部署状态/路径/精度推断已纠正，源码差异与真正未验证项没有伪装成完成。
Path：完整备份→全文状态/路径扫描→源码与证据对照→章节拆分/入口更新→同输入审计→精确包重建与回滚。
