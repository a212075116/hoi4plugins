# 构建方式

## 环境

| 项 | 值 |
|---|---|
| Visual Studio | 2022 Community |
| 平台工具集 | v143 |
| Windows SDK | 10.0.26100.0 |
| 工程设置 | LanguageStandard=stdcpp17；核心.c仍为C源，不能把整个工程当纯C++17 |
| 配置 | Debug|x64 / Release|x64 |

## 命令行构建

```bat
call "C:\Program Files\Microsoft Visual Studio\2022\Community\VC\Auxiliary\Build\vcvars64.bat"
cd /d "<游戏根目录>\hoi4plugins"
msbuild hoi4plugins.sln /p:Configuration=Release /p:Platform=x64
```

产物落在 `build/Release/`：`tbb.dll`、`hoi4_mod_plugin.dll` 与 `hoi4_debug_console.exe`。

单独构建src/plugin/plugin.vcxproj时必须传入工程根的SolutionDir，否则产物可能落入src/plugin/build/Release，部署器仍读取根build/Release，造成旧DLL误部署。优先构建整个解决方案；部署后核对构建、游戏根和归档DLL的SHA-256。

## 部署

保存并退出游戏后，把三个产物拷到游戏根目录（覆盖 `tbb.dll`，新增 `hoi4_mod_plugin.dll`）。外部helper也复制到游戏根；`tbb_real.dll` 保持原版不动。构建不会自动部署。

## 载体的链接特殊性

`carrier.def` 里有 100+ 条导出转发，形如：

```
??0concurrent_queue_base@internal@tbb@@IEAA@_K@Z=tbb_real.??0concurrent_queue_base@internal@tbb@@IEAA@_K@Z
```

其中一部分是**数据导出**（`TBB_runtime_interface_version`、`__TBB_machine_*` 等 11 个）。
对数据导出，链接器不能生成转发桩，会报：

```
carrier.def : error LNK2001: 无法解析的外部符号 TBB_runtime_interface_version
...
fatal error LNK1120: 11 个无法解析的外部命令
```

**绕法**：先用 `lib` 由 .def 生成导入库与 .exp（这一步不校验符号），再把 .exp 交给链接器。
工程里用了一个 `BeforeTargets="Link"` 的 Target 做这件事，而不是直接设 `ModuleDefinitionFile`：

```xml
<Target Name="MakeCarrierImportLib" BeforeTargets="Link">
  <Exec Command="lib /nologo /def:&quot;$(ProjectDir)carrier.def&quot; /out:&quot;$(OutDir)carrier_exp.lib&quot; /machine:x64" />
</Target>
```

并在 Link 的 `AdditionalDependencies` 里加上 `$(OutDir)carrier_exp.exp`。

## 自有源码必须全 ASCII

MSVC 在没有 `/utf-8` 时按系统代码页（简体中文是 936/GBK）解析源文件。
UTF-8 的中文字符串会被误读，症状是：

```
warning C4819: 该文件包含不能在当前代码页(936)中表示的字符
error C2001: 常量中有换行符
```

**本项目的规定**：源码（含日志字符串）全英文，新增/修改的自有源码使用ASCII；第三方MinHook保留原始内容（其中存在非ASCII符号），不因重构改写供应商源码。
`test/tools/strip_comments.py` 带非 ASCII 检查，会在生成时报出残留行。
