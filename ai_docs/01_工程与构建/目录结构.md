# 目录结构

> 根目录：`<游戏根目录>/hoi4plugins/`

## 布局

```
hoi4plugins/
├─ hoi4plugins.sln              解决方案
├─ ai_docs/                     技术文档（本目录）
├─ src/                         源码
│   ├─ carrier/                 载体项目 -> tbb.dll
│   │   ├─ carrier.vcxproj
│   │   ├─ carrier.h
│   │   ├─ carrier.def          100+ 导出转发表（32 KB，由脚本生成）
│   │   └─ carrier_loader.cpp
│   └─ plugin/                  插件项目 -> hoi4_mod_plugin.dll
│       ├─ plugin.vcxproj
│       ├─ plugin_main.c        插件入口（唯一留在这一层的源文件）
│       └─ SDK_RVA/             已逆出的游戏接口，按子模块分目录
│           ├─ console/         控制台相关
│           │   ├─ console_cmd.h    控制台指令注册器（接口）
│           │   └─ console_cmd.c    控制台指令注册器（实现）
│           └─ camera/          摄像机相关
│               ├─ camera_height.h  摄像机模块（接口）
│               └─ camera_height.c  摄像机模块（实现）
├─ test/                        探针与验证脚本（不参与构建）
├─ sources/                     IDA 数据库等 dump
│   └─ 1.19.3/                  按游戏版本分子目录
└─ build/                       构建产物（不在版本控制里的可选）
    ├─ Release/                 tbb.dll, hoi4_mod_plugin.dll
    └─ obj/                     中间文件
```

## 为什么这样分

| 目录 | 理由 |
|---|---|
| `sources/<版本>/` | IDA 数据库与游戏版本强绑定，混在一起必然出错。当前版本 1.19.3。 |
| `test/` | 探针脚本数量会持续增长，混进 `src/` 会让工程不可读。 |
| `src/carrier` 与 `src/plugin` 分开 | 两者职责完全不同：载体只管转发导出，插件才是业务。改动插件不需要重编载体。 |
| `plugin/SDK_RVA/<子模块>/` | 已逆出的游戏接口按功能归目录。**只有 `plugin_main.c` 留在 `plugin/` 根**，它是入口，不属于任何游戏子系统。 |
| 源码不留注释 | 注释与文档双份维护必然漂移。解释集中到本目录。 |

### include 是怎么解析的

源码里一律写 `#include "console_cmd.h"` 这样的**裸文件名**，
靠项目的附加包含目录解析，不写相对路径：

    $(ProjectDir);$(ProjectDir)SDK_RVA\camera;$(ProjectDir)SDK_RVA\console;..\carrier

好处是**移动文件所在目录时不需要改任何源码**（本次重组就没动一行 include）。

## 运行时布局（游戏根目录）

```
Hearts of Iron IV/
├─ tbb.dll                 我们的载体（游戏导入表直接加载它）
├─ tbb_real.dll            原版载体（被转发目标）
└─ hoi4_mod_plugin.dll     我们的插件（被载体 LoadLibrary）
```
