# 摄像机字段

> 全部语义由用户用 Cheat Engine **逐项改写后目视判定**，不是推测
> 原始记录：reports/20261009_150703_原版_CCamera_字段语义用户判定.txt

## 指针链

    cam = *( *(hoi4.exe + 0x332F698) + 0x750 )

getter 是 sub_140DC53B0（RVA 0x0DC53B0）：

    return *(_QWORD *)(a1 + 1872);      // 1872 = 0x750

## 设置高度的 setter（已实证）

除了直接写 `+0x69C`，游戏自己有一个设置函数：

    sub_1412643F0(cam, float h)      // RVA 0x12643F0，净效果 cam+0x69C = h

被 **37 处**引用，是游戏各处设置摄像机高度的公共入口。

### 与直接写字段的实测差异

| 做法 | 超范围输入（如 9999，上限 3000） |
|---|---|
| 直接写 `+0x69C = 9999` | 写入成功，**留下约 2.5 秒的非法值窗口**，之后主循环才夹回 3000 |
| `sub_1412643F0(cam, 9999)` | **当场夹紧到 3000** |

在范围内的正常值（如 1200）两者**可见效果一致** —— 游戏都会平滑过渡。

所以适用场景是：**值可能越界**，或需要同步对象内部状态时用 setter。

### setcamheight 的当前实现（单指令，走 setter）

**只用 setter**，夹紧完全交给它：

    used = Camera_SetHeight(cam, want);
    if (!used) {
        if (lo > 0 && want < lo) want = lo;
        if (hi > 0 && want > hi) want = hi;
        *(float*)(cam + OFF_CAM_HEIGHT) = want;
    }

实测 6 个用例（test/reports/20261009_180808_*.txt）：

| 输入 | 结果 |
|---|---|
| 无参数 | 回显 310.00 |
| 1200 | 立即 1200，1.8s 后当前高度 1199.84 |
| 9999 | **立即 3000**（setter 夹紧） |
| -500 | **立即 50**（setter 夹紧） |
| abc | ok=0，值不变 |
| 310 | 复位成功 |

### 相关函数

| 函数 | 语义 |
|---|---|
| `sub_140DC53B0(idler)` | 取 cam（CInGameIdler 虚表 `+0x130`） |
| `sub_141264150(cam)` | 高度减小（滚轮向下） |
| `sub_1412642A0(cam)` | 高度增大（滚轮向上） |
| **`sub_1412643F0(cam, h)`** | **设置高度为 h** |
| `sub_141261320(cam, ...)` | 内部插值（上面三个都调它） |

`sub_141261320` 里会把 `+0x684`（渲染层副本）夹到 `[+0x6D0, +0x6D4]`。

详见《找 setter 的方法》与 `test/reports/20261009_173105_*.txt`。
## 字段语义（已定论）

| 偏移 | 类型 | 含义 |
|---|---|---|
| **+0x69C** | float | **目标高度（引擎承认的设置入口）** |
| +0x678 | float | 当前高度（游戏自己平滑逼近 +0x69C） |
| +0x684 | float | 渲染层副本（改了会被拉回，非引擎层） |
| +0x6D0 | int | **高度下限** |
| +0x6D4 | int | **高度上限** |
| +0x6F4 | float | 鼠标拖动阻尼（调大后漂移感消失） |
| +0x6F0 | byte | 摄像机锁定标志 |
| +0x674 | float | 位置 X |
| +0x678 | float | 位置 Y（同时就是高度） |
| +0x67C | float | 位置 Z |
| +0x6C8 | int | 视口宽 |
| +0x6CC | int | 视口高 |
| +0x690 | float | 常量 9.5，改写后立即回写 |
| +0x6F8 | int | 疑似 1，改动无明显效果 |
| +0x6FC | float | **语义未定**（与高度负相关） |

## 用户的原话（判定依据）

| 字段 | 用户判定 |
|---|---|
| +0x69C | "你的猜测准确，这个修改后成功改动了摄像机高度（并且遵循摄像机高度上下限）" |
| +0x678 | "这个的确和你描述的一样" |
| +0x684 | "似乎是渲染层，并不是引擎层面认可的高度（即修改了之后视角突然从我修改的高度拉回到修改前的高度）" |
| +0x6F0 | "这个你判断正确" |
| +0x6D0/+0x6D4 | "判断正确" |
| +0x674/+0x67C | "的确是" |
| +0x6F4 | "我测试了数值改动之后，当摄像机视角被鼠标拉动而移动后，摄像机视角原本会有点初速度感（漂移感），在数值改动高之后，漂移感消失了" |
| +0x6F8 | "修改了之后没什么变化" |
| +0x690 | "后者是修改之后立马变回原值" |

## 两次独立实验互证

| # | 做法 | 结果 |
|---|---|---|
| 1 | 我方主动写 0x69C = 400 | 12 次读回恒为 400.0000；0x678 由 402.87 收敛至 400.15 |
| 2 | 用户滚轮拉到最近 | 0x69C 恒为 310.0000；0x678 由 801.16 收敛至 310.04；0x6FC 由 0 收敛至 4453.18 |

**结论**：+0x69C 是输入，+0x678 是输出（游戏自己平滑）。
