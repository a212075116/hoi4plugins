# 游戏日期的界面显示链路

> 本页讲「界面上的日期文本从哪来、怎么更新」；
> 日期本身的内存布局与编码见《游戏日期.md》。

## 界面日期的完整更新链路（含「暂停时也能刷新」的方案）

### 界面元素叫 `DateText`

`sub_14189EF20`（UI 更新总入口，每帧被 `sub_14189ECF0` 调用）里：

```asm
0x1418a00da  lea  rdx, aDatetext; "DateText"    ; ★ 元素名
0x1418a00e8  call sub_14011D970                  ; 构造名字
0x1418a00f8  mov  rcx, r12
0x1418a00fb  call rbx                            ; 虚调用: 按名字查元素
0x1418a00fd  mov  [rdi+80h], rax                 ; ★ 存到面板+0x80
0x1418a0110  mov  rcx, rdi
0x1418a0113  call sub_1418A1EE0                  ; 更新它
```

### 更新函数 `sub_1418A1EE0`（RVA `0x18A1EE0`，仅 305 字节）

```c
__int64 __fastcall sub_1418A1EE0(__int64 a1, __int64 a2)
{
  v2 = *(_QWORD *)(a1 + 128);                                   // DateText 元素
  ...                                                           // gamestate 断言
  v4 = sub_140533460((__int64)gs + 1120, (__int64)v6, 1u);      // gs+0x460 格式化
  return sub_1422CA920(v2, v4);                                 // 设文本
}
```

### 实测（Frida）

    hook sub_1418A1EE0: 12 秒 1638 次 ≈ 137 次/秒
      a1 = 0x269efe0e010      (每帧同一个, 稳定)
      *(a1+128) = 0x269f879cb80

    主动调用 sub_1418A1EE0(a1, 0):
      #1 -> ret=0x0      #2 -> ret=0x6b      游戏存活 ✓

**⇒ 主动调用是安全可行的。**

### 为什么暂停时界面不动

暂停时实测 `sub_140533460` 与 `sub_1418A1EE0` **调用次数都是 0** ——
整条 UI 链不跑，所以看不到变化。**这不是缺标志位，而是链本身停了。**

### 让暂停时也刷新的方案

改完 `+0x468` 之后，手动调一次：

    sub_1418A1EE0(a1, 0)      // a1 是 UI 面板, *(a1+0x80) = DateText 元素

`a1` **没有静态指针**（扫全内存找不到指向它的 qword），所以只能运行时抓一次。
做法：给 `sub_1418A1EE0` 装一次性 detour，第一次调用时记下 `a1` 后立刻拆掉；
以后每次改日期调一次即可。

### 调用的安全性

`sub_1418A1EE0(a1, a2)` 里 `a2` 只在 TLS 按需初始化时用，传 0 即可；
函数自身带 gamestate 断言（`_ThreadForbidCount == 0`），所以
**必须在游戏主线程调用**，不能在别的线程里调。
## 插件实现（已完成并验证）

### 用 MinHook 装 inline hook

`SDK_RVA/hook/inline_hook.c` 是对 MinHook 的薄封装（`InlineHook_Init/Install/Remove`），
**MinHook 放在 `SDK_RVA/minihook/`**（从 https://github.com/TsudaKageyu/minhook 取得，
commit `8af6b4a`，**BSD 2-Clause**，见同目录 `LICENSE.txt`；已删除其 `.git` 以便随本仓库管理）。

参与编译的文件（x64 只需这些）：

    minihook/src/hook.c
    minihook/src/buffer.c
    minihook/src/trampoline.c
    minihook/src/hde/hde64.c

早先的 `SDK_RVA/hook/*.c` 走的是 **IAT hook**（改导入表指针），
只能拦 `kernel32` 之类的导入函数；**游戏内部函数必须用 inline hook**。

### 为什么要 hook（而不是只调一次）

`sub_1418A1EE0` 的两个参数里，`a1`（UI 面板）**没有静态指针**
（全内存扫不到指向它的 qword），只能在它被调用时抓。
它每帧都被调（实测 137 次/秒），所以：

```c
static long long __fastcall Hook_UiDateUpdate(void* panel, void* unused)
{
    if (g_uiPanel == NULL && panel != NULL) {
        g_uiPanel = panel;                    // 只抓一次
        Plugin_Log("[gamedate] ui panel captured: %p", panel);
    }
    return g_origUiDate(panel, unused);       // 原样转发
}
```

hook 本身极轻量（一次判空 + 尾调用），常驻没有可感开销。

### 改日期后主动刷新

`GameDate_SetRaw` 写完 raw 与派生字段后调 `GameDateUi_Refresh()`：

```c
int GameDateUi_Refresh(void)
{
    if (g_uiPanel == NULL || g_origUiDate == NULL) return 0;
    r = g_origUiDate(g_uiPanel, NULL);        // 等价于走一帧 UI 更新
    ...
}
```

这样**即使游戏暂停**（整条 UI 链不跑），界面上的 `DateText` 也会立刻更新。

### 线程约束（重要）

`sub_1418A1EE0` 内部有 gamestate 断言（`_ThreadForbidCount == 0`），
所以必须在**主线程**调用。控制台命令与 effect 的执行都在主线程
（实测 `ui refresh` 调用未触发断言，游戏稳定），因此直接调用是安全的。
若将来发现异常，应改为「只置一个待刷新标记，由 hook 在本帧转发时执行」。
