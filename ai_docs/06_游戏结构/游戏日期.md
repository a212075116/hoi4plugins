# 游戏日期 (CGameDate / CGregorianDate)

> 全部为 1.19.3 实测。原始记录：`test/reports/20261010_0310_原版_CGameState_日期修改_完整测试.txt`

## 结论

**游戏内日期可以修改。** 真源是一个 int32，写进去后游戏在下一个 tick 重算年/月/日，
`game.log` 的日期前缀也随之改变（实测 500 → 510 → 520）。

**写入不会让游戏崩溃。**（早前记录过一次"游戏退出"，后经查证那**不是崩溃**，
是测试脚本用 `frida.spawn` 启动游戏、脚本结束时宿主进程把游戏一起终止了，
详见《关于那次"游戏退出"》一节。）

## 内存布局（实测）

    CGameState = *(hoi4.exe + 0x332F260)

| 偏移 | 内容 |
|---|---|
| +0x460 | 内嵌 CGameDate 对象（虚表 RVA `0x27183A8`） |
| **+0x468** | **日期真源，int32，单位 = 小时** |
| +0x470 | 内嵌 CGregorianDate（虚表 RVA `0x27181B0`，在 CGameDate+0x10 处） |
| +0x478 | 年（派生，每 tick 重算） |
| +0x47C | 本月天数（派生；2月=28，6月=30，7月=31） |
| +0x480 | 日（派生） |
| +0x484 | 年内第几天 dayOfYear（派生；2月1日 = 32） |
| +0x488 | 月 − 1（派生，0-based；6月 = 5） |

`+0x4A0` 处还有另一个内嵌 CGameDate，字段不同，本次未纳入结论。

## 日期编码

来自 IDA 反编译 `sub_140533D60`（字符串 → 日期，格式 `%d.%d.%d.%d`）：

    v4   = *(int*)(this + 8) - 43800000;   // 43800000 = 基准小时数
    天数 = v4 / 24;                        // 单位是小时，1 天 = 24
    年数 = 天数 / 365;                     // 每年固定 365 天，无闰年

    每月天数表在静态地址 0x143085210

换算公式：

    值   = 43800000 + 天数 * 24 + 小时
    天数 = 365 * (年 - 500) + 前面各月天数之和 + (日 - 1)
    每月天数 = [31,28,31,30,31,30,31,31,30,31,30,31]

实测锚点：**500.1.1 时 raw = 48180000** ⇒ 天数 = 182500 ⇒ 182500 / 365 = 500 ✓

## 验证证据

### 1. 只读派生字段与日志逐项吻合

| 时刻 | game.log 前缀 | +0x478 | +0x47C | +0x480 | +0x484 | +0x488 |
|---|---|---|---|---|---|---|
| T1 | `[0500.01.19.01]` | 500 | (1月) | 19 | 19 | 0 |
| T2 | `[0500.02.02.01]` | 500 | **28** | 1 | **32** | **1** |

`+0x47C = 28` 正是 2 月天数；`+0x484 = 32 = 31+1` 即 2 月 1 日；`+0x488 = 1` 即 0-based 的 2 月。

### 2. 写派生字段无效（反证）

| 写入 | 2 秒后读回 |
|---|---|
| `+0x478 = 510` | 500 ✗ |
| `+0x47C = 2` | 31 ✗ |
| `+0x480 = 25` | 18 ✗ |

⇒ 它们是缓存。**必须写 `+0x468`。**

### 3. 写真源成功（日志确认）

| # | 操作 | 结果 |
|---|---|---|
| 1 | raw += 3650×24 | 派生 `+0x478=510`；日志变成 `[0510.06.26.01]` ✓ |
| 2 | raw += 3650×24 | 派生 `+0x478=520`；日志变成 `[0520.07.07.01]` ✓ |
| 3 | 设为 `510.6.7` | 派生 `+0x478=510 +0x47C=30 +0x480=6 +0x488=5`（差 1 天，见下） |
| 4 | 紧接着设 `515.3.20` | **游戏退出** ✗ |

## 已知偏差

按公式算出的 `510.6.7` 写入后，派生字段显示 **510 年 6 月 6 日**（差 1 天）。
原因未定。**落地时必须用「写入后读回派生字段」做校验，不能只信公式。**

## 关于那次"游戏退出"（已查明，不是崩溃）

早前记录过一次"写入后游戏退出"，当时怀疑是写入导致的。**该判断是错的。**

**证据表明游戏不是崩溃：**

| 检查项 | 结果 |
|---|---|
| `%LOCALAPPDATA%\CrashDumps` | 无 hoi4 的 .dmp |
| Windows 应用程序事件日志 | 该时段**无任何** Application Error 记录 |
| `crashes/` 目录 | 无新目录（最新一个是更早的其它测试） |

**真正原因：** 那次测试用的启动脚本走 `frida.spawn`，
而 `frida.spawn` 出来的进程**会随宿主 Python 进程结束而被一起终止**。
任务记录里 `pwsh-218`（启动脚本）的结束时刻是 `03:08:47`，
与"游戏退出"的观测时刻**是同一秒**，而它启动于 02:51:12 —— 也就是说它一直挂着，
最后退出时把游戏带走了。

**对照实验（决定性）：**

| 启动方式 | 脚本退出后游戏 |
|---|---|
| `frida.spawn`（脚本自己拉起游戏） | **被终止** ✗ |
| `frida.attach`（游戏由 `Start-Process` 独立启动） | **仍存活** ✓ |

**结论：** 改日期不会崩游戏。但**测试/使用时要让游戏由独立进程启动再 attach**，
否则脚本一退出游戏就没了，会被误判成崩溃。

### 另一次对照：主菜单下连写 3 次

在**主菜单**（未进战略地图）时连续写入 `510.6.7` → `515.3.20` → `500.1.1`，
三次全部写入成功、值保持、游戏安然无恙。此时派生字段不重算（因为游戏没在跑），
所以读回 `+0x478` 等仍是初始值 —— **不要用派生字段判断写入是否成功，要直接读 `+0x468`。**

## 相关函数（RVA）

| RVA | 语义 |
|---|---|
| `0x0533D60` | 字符串 → 日期（`%d.%d.%d.%d`），含 `Invalid date` 校验 |
| `0x05339E0` | CGameDate 反序列化：从流读一个 int 写入 `(this-8)` |
| `0x0533F70` | CGameDate 序列化 / 属性交换 |
| `0x23A5DA0` | CGregorianDate 属性交换（`a2+0xC0 == 3` 时走日期分支） |
| `0x23A6200` | 日期属性处理 |

## 复现步骤

1. 带 `-start_tag=<有效tag>` 启动，等进战略地图
2. 控制台 `auto_unpause 3`（**不取消暂停日期不会推进**）
3. Frida attach，`*(hoi4.exe+0x332F260)` 取 CGameState
4. 读写 `CGameState+0x468`（int32，单位小时）
5. 校验：读 `+0x478`(年) `+0x488`(月−1) `+0x480`(日)，并对照 `game.log` 的行前缀

`game.log` 每行前缀形如 `[0500.01.01.01]` = 年.月.日.小时，是独立的校验源。


## 游戏自己的 setter（`sub_140533D60`）

与摄像机高度那次一样，日期也有游戏自己的设置函数：

    char sub_140533D60(CGameDate* this, std::string* text)
    // 1. 用 "%d.%d.%d.%d" 解析（年.月.日.小时），段数 <= 2 时返回 0
    // 2. 内部完整计算（每月天数表在 0x143085210、按 365 天/年）
    // 3. 写 *(int*)(this + 8) = 计算出的日期值
    // 失败时调用方打印 "Invalid date "

`this + 8` 就是 **`CGameState + 0x468`**（因为 `CGameDate` 在 `CGameState+0x460`）。

**它被谁调用：** `CGameDate` 的虚函数（序列化/反序列化路径，即存档读写）：

| 调用点 | 函数 | 语义 |
|---|---|---|
| `0x140533a5f` | `sub_1405339E0` | CGameDate 反序列化（同样直接写 `this+8`） |
| `0x14154023a` | `sub_141540190` | CGameDate 虚函数，属性交换 |
| `0x1415a1639` | `sub_1415A15A0` | CGameDate 虚函数，属性交换 |

后两个虚函数所属的虚表在 `0x1429d5d10` 附近（表头 `0x1429d5d38 - 0x28`），
其中 `+0x28` 槽 = `sub_141540190`；另一个表在 `0x1429db8f8` 附近，`+0x28` 槽 = `sub_1415A15A0`。

**能不能当 setter 用：** 可以调用，但它**只写那一个 int**，
与直接写 `CGameState+0x468` **效果相同**，不会额外同步任何东西。
所以它并不能避免崩（本来也不会崩，见上一节）。
它的价值在于提供了官方的日期字符串解析与换算，省得自己套公式算错。

**注意**：调用前需保证目标对象 `this` 的虚表是合法的 `CGameDate` 虚表；
`CGameState+0x460` 本身就是合法对象，可直接传。
