# 载体原理

> 源码：src/carrier/carrier_loader.cpp
> 产物：tbb.dll（替换原版）

## 为什么要有载体

游戏 hoi4.exe 的导入表里写死了要从 tbb.dll 取一批函数（Intel TBB 并行库）。
Windows 加载器只会在**游戏根目录**找它。于是：

1. 把原版 tbb.dll 改名成 tbb_real.dll（内容不动）。
2. 我们自己编一个 tbb.dll 放在原处。
3. 它把**全部导出**转发给 tbb_real.dll，游戏功能不受影响。
4. 顺便用绝对路径 LoadLibrary 加载插件 hoi4_mod_plugin.dll。

这样整套东西收敛成"游戏根目录里的几个文件"，与 mod 布局彻底解耦。

## 导出转发

carrier.def 由脚本生成，32 KB，形如：

    LIBRARY tbb
    EXPORTS
        ??0concurrent_queue_base@internal@tbb@@IEAA@_K@Z=tbb_real.??0concurrent_queue_base@internal@tbb@@IEAA@_K@Z
        ...

**链接特殊性见 ai_docs/01_工程与构建/构建方式.md**（数据导出需要先 lib /def: 出 .exp）。

## 插件加载

    static const char* kPluginNames[] = {
        "hoi4_mod_plugin.dll",
        "mod_plugin.dll",
        "plugin.dll",
        NULL
    };

按顺序找**第一个存在**的，用绝对路径 LoadLibraryA。

**注意**：不能把与载体同名的 tbb.dll 列进来——那会把引导器自己再加载一遍，递归。
